raz is a small systems language, first made for x86-64 Linux. A raz program can lay a record over a device’s registers, read and write a device’s memory exactly as written, take part in lock-free algorithms, make system calls and call C libraries. It has no garbage collector and no hidden run time: what the program does is what its text says.

This is the first volume of the report: the language, what an implementation chooses, and the grammar. The second, doc/raz-lib.md, is the library, which sections 3 and 10 and appendix A name.

This report defines the language. It is short on purpose. Whatever it doesn’t allow, raz doesn’t have.

1. A first look

module Hello;
import Out;

proc main*;
begin
    Out.str("hello, world\n");
end;

end Hello.

A program is a set of modules. The one named on the command line is the main module, and it exports a procedure main; the program starts there, once every module’s body has run (section 3). Saved as Hello.raz, it is compiled with raz Hello.raz, which writes the executable Hello.

2. Words and symbols

A program is written in UTF-8. The compiler rejects a file that isn’t valid UTF-8: a malformed or overlong sequence, a surrogate, or a code point beyond 10FFFFH, and a file with a NUL byte. Everything outside strings, characters and comments is ASCII. Spaces, tabs and line breaks separate symbols and are otherwise ignored.

Identifiers are an ASCII letter or _ followed by letters, digits and _, up to 63 characters. Case matters: count and Count are different names. _ alone isn’t a name: it is the blank, which stands only to the left of := (section 7.1).

Reserved words are lowercase, except VOLATILE:

and begin break by code const continue defer div do else elsif end
extern for forward if import in link match mod module not of or packed
proc record repeat return set shl shr then to try type until var
variant VOLATILE while xor

static, in link static; (section 3), and check and off, in check off; (section 3), aren’t reserved.

Predeclared names are the basic types (section 5.1), ERROR, true, false, nil and the built-in procedures (section 6.8). They belong to a scope around every module, so a module or a procedure may declare the same name for something else, which hides them there.

Numbers. 123 is decimal. 0FFH is hexadecimal: it starts with a digit, its digits are 0 to 9 and A to F, and it ends in H, all in capitals. 1.5 and 2.0E-3 are reals; a real always has a digit on both sides of its point, and its exponent, if it has one, is E, a sign if wanted, and digits. A decimal number above the largest I64, or a hexadecimal one above the largest U64, is an error; so is a real above the largest F64. A real below the least F64 is 0.

An integer is an untyped constant, which takes the type it is used as, up to the largest I64. A hexadecimal number above that, such as 0FFFFFFFFFFFFFFFFH, has type U64: so -1 never fits a U64, and the big number goes nowhere else without a conversion. Arithmetic on untyped constants doesn’t wrap: a result beyond the I64s, such as 9223372036854775807 + 1, is an error.

A real is an untyped constant too. It is read as the nearest F64 (a tie goes to the even one), and takes F32 or F64, whichever it is used as: an F32 is the nearest to that F64. Where nothing says which, it is an F64. A real never becomes an integer, nor an integer a real, without a conversion: x := 1; is an error for x: F64, and x := 1.0; is right.

Characters. 'a' is the code point of one character, an integer: 'a' is 97 and 'é' is 233.

Strings. "héllo\n" is a sequence of bytes, the UTF-8 of its text: "é" is the two bytes 0C3H, 0A9H. Both characters and strings take the escapes \n (line feed), \t (tab), \r (carriage return), \0 (zero), \\, \', \", \u{H...} (the code point with hexadecimal value H…, up to 10FFFFH, in a string its UTF-8) and, in strings only, \xHH (the byte with hexadecimal value HH, which needn’t make valid UTF-8). In an escape, the hexadecimal digits may be capitals or not. A character, or a string in double quotes, ends on the line it starts on.

Raw strings. `C:\tmp\"a b"` is a string written between backquotes: its bytes are the text between them as it stands, with no escapes, so \ and " are themselves. A raw string may run over lines, and each line break in it is a line feed, part of the string; a carriage return in it is left out.

A raw string whose opening backquote ends its line, and whose closing backquote has only blanks (spaces and tabs) before it on its line, is indented: the text is its lines between those two, each without the closing line’s blanks at its start, and each ending in a line feed. So a long text may stand at the indentation of the code around it:

proc usage;
begin
    Out.str(`
        usage: tool [-v] file ...
          -v  say what is done
        `);
end;

writes "usage: tool [-v] file ...\n -v say what is done\n". Each line of an indented raw string must start with the closing line’s blanks, the same spaces and tabs in the same order, or it is an error; a line holding only blanks is an empty line of the text. A raw string that isn’t indented is the text between its backquotes as it stands.

A raw string can’t hold a backquote; a text that needs one joins it with +, as "`". Everywhere else a raw string is a string, as one in double quotes is.

Messages give the line and the column, counted in characters (section 10).

Comments are (* … *) and nest. A comment ends at the *) that closes it, wherever that stands, so one that quotes *), as in x*) of a pattern, writes it apart: x* ). By convention, the comment just before an exported declaration is its documentation, and the one before module is the module’s.

Operators and delimiters:

+  -  *  /  &  |  ~  =  #  <  <=  >  >=  :=  :  ;  ,  .  ..  ...  (  )  [  ]  {  }  ^

| is also what starts an arm of match (section 7.4); an arm comes where a statement could, never after an operand, so the two don’t mix.

3. Modules

Module     = "module" ident [ "(" ModParams ")" ] ";"
             { Import } { Link } [ Check ] { Declaration }
             [ "begin" Statements ] "end" ident "." .
ModParams  = ident { "," ident } { ";" ident ":" "proc" Signature } .
Import     = "import" ImportItem { "," ImportItem } ";" .
ImportItem = ident [ ":=" ident [ "(" Type { "," Type } ")" ] ] .
Link       = "link" ( string | "static" ) ";" .
Check      = "check" "off" ";" .

A module lives in a file of its own name: module Out is Out.raz. The name after end repeats the module’s name.

Exports. A name declared at the top of a module with * after it is exported: other modules can use it as Module.name. Record fields are exported the same way. Everything else is private to the module. An exported variable can be read by the modules that import it, but only its own module changes it. Outside it, the variable is a value, not a variable: nothing that could write it, or let something else write it, may name it or a field or element of it. So it can’t be assigned, passed as a var argument, changed by INC, DEC or NEW, or given to SYSTEM.ADR; an array in it is sliced, or used where a slice is expected (the silent conversion of an array, section 5.10), only as a []const T, whose elements can’t be written (section 5.3); a slice in it may be sliced, since that makes a new slice and can’t change the variable; in match, its arms’ names stand for the fields of a copy. It can be read, copied and compared, and a copy is the importer’s own. What a pointer or a slice in it points at is another variable, and isn’t held to this: with s: []U8 exported, M.s[0] := 0 writes what M.s points at, not M. A module that means to share an array for reading exports it; for writing, it exports a pointer to it, or a procedure that returns a slice of it.

Imports. import Out; makes Out’s exports available as Out.x. import O := Out; uses the name O instead. A module can’t import itself, directly or through others.

import SYSTEM. SYSTEM is no file but a module the language gives, of the operations that reach memory other than through the program’s variables, or let something outside the program do so. A module that does any of these says import SYSTEM;, and it is an error to do them in one that doesn’t:

  • SYSTEM.ADR, SYSTEM.PTR, SYSTEM.SYSCALL and SYSTEM.ARGV (section 6.8), which are written so, by that name;
  • p + i, p - i, p[i] and p[lo..hi] on a pointer (section 6.4);
  • a conversion to a pointer or a procedure type from an integer or from another pointer or procedure type, or from a pointer or a procedure to an integer (section 6.7), and a string literal given where a ^U8 is wanted (section 5.10);
  • a view whose type holds a pointer, a view written over a variable whose type holds anything but integers and reals, and BYTES of such a variable (sections 6.8 and 6.9);
  • extern and link of a library (section 9), code procedures (section 8) and check off; (below).

SYSTEM can’t be imported under another name, so that every module that reaches memory so says it by that name. What such a module does is its own to get right: section 10 says what isn’t defined. A module that imports one that says import SYSTEM needn’t say it itself; it trusts that module as it trusts the library, whose Rt, Mem, Heap, Sys, Thread and others say it.

Generic modules take types as parameters:

module List(T);
type
    Node* = record next*: ^Node; val*: T; end;
...
end List.

An import gives the arguments: import Ints := List(I64);. Each distinct list of arguments makes one instance: the module compiled with T standing for I64. Two imports of List(I64), in any modules, share one instance, its variables and its ERRORs with it: two lists of arguments are the same when their types are the same (section 5.10), an alias as what it stands for, and their procedures are the same procedures. Since every instance is checked on its own, an operation the argument type doesn’t support (adding two records, say) is reported as an error in that instance.

An instance is made where its module is first used, not at the import: so the arguments may name types the importing module declares after its imports, as long as they are declared before that first use. The instance is made before the code of the procedure, or the module body, that first uses it, and its arguments are read in the scope there.

import Table := Map([]const U8, Colour, Str.hash, Str.eq);

type Colour = (red, green, blue);

var names: Table.Map;   (* the instance is made here *)

What a generic module needs to do with its types, beyond moving them about, it is given as procedures, after the types:

module Map(K, V; hash: proc(k: K): U64; eq: proc(a, b: K): BOOL);
import Names := Map([]const U8, I64, Str.hash, Str.eq);

A procedure argument names a procedure, not a variable or an expression, and its signature, with the type arguments put in, must be the parameter’s. Inside the module, hash(k) calls it directly. Two imports make the same instance only if their types and their procedures are the same.

Finding modules. The compiler looks for module Name in the main module’s directory, then in each directory given with -I, then in the user library directories, then in the lib directory beside the compiler. User libraries live in $HOME/.raz/lib by default. RAZ_PATH, when set, replaces that default with a colon-separated list of directories; an empty value disables user libraries. Empty entries are ignored. With no nonempty HOME, there is no default. Paths are not searched recursively; relative paths are relative to the compiler’s working directory, and ~ and variables inside them are not expanded. Install a library’s source files directly in one of these directories, with its target-specific files beside them. In each directory the compiler takes the first of Name.OS-ARCH.raz, Name.OS.raz, Name.ARCH.raz and Name.raz that exists, where OS-ARCH is the target, for now only linux-x86_64. So a module whose code depends on the machine or the system comes in one file per target, and the modules that import it don’t change. Machine code (section 8) and system calls belong in such files.

One module to a name. A program has one module of each name, so the compiler reports an error, naming the files, if a module it looks for has files in more than one of these directories, rather than take the first: a Buf.raz beside a program would otherwise stand in for the library’s Buf in every module that imports it, the library’s own among them. A link is the exception: a file that is a symbolic link to one of the module’s files in a later directory chooses that file, so that a directory holding a link to lib/Sys.raz builds a program over the C library’s Sys on Linux too.

Names are flat. The names of a program’s modules are one space, with no packages or paths. So the names of the library’s modules (the library, doc/raz-lib.md) are kept for it: a program or another library doesn’t name a module of its own Arena, Buf, C, Files, Fmt, Guarded, Heap, List, Lock, Map, Math, Mem, Opt, Out, Rt, Sort, Str, Sys, SYSTEM, Task or Thread, nor any name the library takes later. The modules of any other library share a prefix of their own, as an X11 library’s Xauth and Xkeys do, and a program that wants a shorter name imports one: import Auth := Xauth;.

The compiler holds every file of such a module to the same interface. When it takes one of Name.*.raz, it also reads the declarations of the others beside it, and of Name.raz if there is one, and reports an error unless they all export the same names, each the same kind of thing:

  • a constant of the same type (its value may differ: a system call number, say);
  • a type of the same kind, and for a record or variant the same exported fields and cases, with the same types (unexported fields, and so the size and layout, may differ);
  • a variable of the same type;
  • a procedure of the same signature.

Two types here are the same if they are built alike, a name in one file standing for the same name in another.

Module bodies. A module may end with begin and statements, its body. Every module’s body runs once, before the main module’s main: a module’s body runs after the bodies of the modules it imports, in the order of its imports, and once however many modules import it. Each instance of a generic module has its body run once. Module variables are zero before any body runs. return; ends a body early.

link "libX11.so.6"; names a shared library to load at run time, for the extern declarations of section 9, in a module that imports SYSTEM. link static; says the module needs a program without C (section 10): it makes its own system calls, or its own threads, which the C library wouldn’t know about.

check off;, after the links, in a module that imports SYSTEM, leaves out of the module’s own code the checks of indexes and slice bounds of section 6.5, and that a slice of a pointer doesn’t run backwards (section 6.4), for speed where the program is sure of them. An index out of range there reads or writes whatever memory it reaches, and what follows isn’t defined. Every other check stays, and the module’s callers keep theirs. An instance of a generic module follows the generic module’s own check line, not that of the module that made it.

4. Declarations

Declaration = "const" { IdentDef [ ":" Type ] "=" Expr ";" }
            | "type" { IdentDef "=" Type ";" }
            | "var" { IdentList ":" Type ";" }
            | ProcDeclaration ";"
            | ExternDeclaration ";" .
IdentDef    = ident [ "*" ] .
IdentList   = IdentDef { "," IdentDef } .

A name must be declared before it is used, with two exceptions: the base type of a pointer may name a type declared later in the same type section (so that two records can point at each other), and so may a parameter or a result of a procedure type there, however passed (so that a record’s callback can take the record, section 5.9); and a procedure may be declared forward and defined later (section 8).

Constants are evaluated by the compiler. Their expressions use only literals, other constants, operators, conversions, SIZE, OFFSET, the LEN of arrays and strings, MIN, MAX, ABS, ROL, ROR, CLZ, CTZ, POPCOUNT, and a variant’s cases. A constant is an integer, a real, a BOOL, a name of an enumeration, a set, a string, an array, a record, a variant or an ERROR. A constant of an integer type wraps as the program would: U8(250) + 10 is 4. Dividing by zero in a constant is an error, and so is dividing the smallest value of a signed type by -1, with div or mod, which stops a program (section 6.1). A string constant can be indexed and sliced as an array of U8 is, and its LEN is its length in bytes. + joins two string constants into one:

const Text = "the cat";
    Line = Text + "\n";
...
w := Text[4..7];    (* "cat" *)

A constant with a type is an ERROR (section 5.8), an array, a record or a variant, and the value of an array or record constant is a literal (section 6.5) of constants, that of a variant one a case built from constants, as a program builds one (section 5.6). Its elements and fields are integers, reals, BOOLs, enumerations, sets, ERRORs, procedures, nil, a string for a []const U8, an array constant, an array literal or the empty slice for a []const T of its element type, and arrays, records and variants of these; no other pointer. A named constant stands for its literal wherever an array, record or variant is wanted. A variant constant must have a type: const D = dot; is an error, const D: Shape = dot; isn’t.

const Primes: [5]I64 = [2, 3, 5, 7, 11];
type Rule = record class: []const U8; tag: INT; float: BOOL; end;
const Rules: [2]Rule = [{class: "firefox", tag: 2}, {class: "mpv", float: true}];
const Shapes: []Shape = [circle(1.0), rect(2.0, 3.0), dot];   (* Shape of section 5.6 *)
const Rows: [][]const INT = [[1, 2], [3]]; (* each row an array constant of its own *)
...
p := Primes[i];

It is used as a variable of that type is, but can’t be changed: an array constant can be indexed and sliced and its LEN is n, a record constant’s fields can be read, and either can be assigned, compared as its type allows, and passed. A slice of it, or of an array in it, is a []const T (section 5.3), as a string’s is. A part of it isn’t a constant, even at a constant index.

An array constant may be typed []T, with no length: its length is then its literal’s, as a string constant’s is the string’s, and it is an array constant of that length, [n]T, in all else. If its literal is [], it is no array but the empty slice, as a slice variable starts: a value of type []T, used as a slice is, and LEN of it is 0 but not a constant.

const Wide: [][2]I32 = [[1100H, 115FH], [2E80H, 303EH], [0AC00H, 0D7A3H]];
    Count = LEN(Wide);        (* 3, a constant *)
    Narrow: [][2]I32 = [];    (* the empty slice *)

Variables of a module live as long as the program; variables of a procedure live as long as its call. Both start at zero: every byte of them is zero. So a number starts as 0 (0.0 for F32 and F64), a BOOL as false, a pointer, procedure or ERROR as nil, a slice as the empty slice (ptr is nil, len is 0), a variant as its first case with its fields zero, a set as the empty set, and an enumeration as its first name. No variable is ever read before it has a value.

5. Types

Type      = QualIdent
          | "[" Expr "]" Type                 (* array *)
          | "[" "]" [ "const" ] Type          (* slice *)
          | "^" [ "VOLATILE" ] Type           (* pointer *)
          | [ "packed" ] "record" { IdentList ":" Type ";" } "end"
          | "variant" { Case ";" } "end"
          | "(" ident { "," ident } ")"       (* enumeration *)
          | "set" "of" QualIdent
          | "proc" Signature .
Case      = ident [ "(" FieldList { ";" FieldList } ")" ] .
FieldList = ident { "," ident } ":" Type .
QualIdent = [ ident "." ] ident .

5.1 Basic types

Type Size Values
I8 I16 I32 I64 1, 2, 4, 8 signed integers, two’s complement
INT an address’s: 8 on x86-64 signed, as big as an address
UINT an address’s unsigned, as big as an address
U8 U16 U32 U64 1, 2, 4, 8 unsigned integers
BOOL 1 false (0), true (1)
F32 4 IEEE 754 single precision
F64 8 IEEE 754 double precision

INT is the everyday integer: lengths, indexes and sizes are INTs. It is as big as an address, and at least 16 bits, as UINT is, on every target; so it is the integer a pointer converts to (section 6.7), and a word the atomic built-ins work on (section 6.8). INT and I64 are two types, even where they have the same size: an INT goes silently into an I64 wherever it meets one, in an expression too (sections 5.10 and 6.1), and an I64 becomes an INT only by INT(x), which may drop bits on a smaller target. A type bigger than the largest INT in bytes is an error.

F32 and F64 exist only on a target that has reals (appendix A). On one that hasn’t, a real literal, and a use of F32, F64 or of a name whose type is made of them, is an error; a declaration that no used code names isn’t, so a module like Fmt keeps one interface on every target.

Each is aligned as the target’s C aligns it: to its size on x86-64. So are ERROR (section 5.8), pointers and procedures, each as big as an address; a slice is aligned as an address is.

5.2 Arrays

[n]T is n elements of type T, one after another. n is a constant greater than zero. Arrays are values: assigning one copies it.

5.3 Slices

[]T is a view of elements that live elsewhere: a pointer to the first and a count, two addresses’ worth, 16 bytes on x86-64.

Slice = record ptr: ^T; len: INT; end;    (* its layout *)

A slice is made from an array (a[2..5], or an array used where a slice is wanted), from another slice, or from a pointer (p[0..n]). It doesn’t own what it points at. LEN(s) is its count, and SYSTEM.PTR(s) its pointer (section 6.8).

[]const T is a slice whose elements can’t be written through it. It is laid out as []T is. Its elements are read, and it is sliced, and a slice of it is a []const T too; but an element of it isn’t assigned, given to COPY or FILL as the destination, changed by INC or DEC, passed as a var argument, or written through a view, and SYSTEM.ADR of one is an error. A []T and an array of T go silently where a []const T is wanted, never the other way (section 5.10). So a procedure that only reads a slice takes a []const T, and every caller’s slice or array fits it:

proc count(s: []const U8; c: U8): INT;   (* reads s, and says so *)

A string literal and a slice of a constant are []const T (sections 4 and 5.10). Another slice may still point at the same elements and write them: const says what this slice may do, not what the elements are.

5.4 Pointers

^T is the address of a T, as big as an INT. nil is the pointer to nothing.

^VOLATILE T is the address of a T that something besides the program may read or change: a device register, memory shared with another process. Section 7.6 says what that promises.

5.5 Records

type Cell = record ch: U8; attr: U8; end;

Fields are laid out in order as C lays them out: each at the next multiple of its own alignment, and the whole record padded to a multiple of its largest alignment. A record declared like a C struct has the same layout as that struct. A record may have no fields; its size is then 0.

A packed record has no padding: each field starts at the byte after the field before it, and the record’s alignment is 1. So a field of a packed record may sit at any address. It is read and written like any other, on every target, even one whose machine can’t reach a misaligned word in one access: the compiled code reaches it in parts there. But a field of a packed record whose type is aligned to more than 1 byte, and anything inside it, has no address: SYSTEM.ADR of it, a var parameter of it and a slice of it are errors. Nor can it be reached through a ^VOLATILE pointer, since a misaligned access can’t be promised as one access (section 7.6). Its value can be copied out and back in.

The bytes of a value of more than one byte are in the target’s order (appendix A). A file or a message in an order of its own is read and written a byte at a time, as Str.le, Str.be, Str.putLE and Str.putBE do (the library, doc/raz-lib.md).

5.6 Variants

A variant holds one of several cases, each with its own fields:

type
    Shape* = variant
        circle(r: F64);
        rect(w, h: F64);
        dot;
    end;

The case names are declared in the scope around the type, so circle can be used directly, and as Shapes.circle from another module if Shape is exported. A case with fields is built by calling it like a procedure, circle(2.0); a case without fields is just dot. The only way to read the fields is match (section 7.4).

Layout: an INT tag (0 for the first case, 1 for the second, and so on), then the space for the fields. Each case’s fields are laid out in that space as a record’s would be, after the tag, and the cases share it, so the variant is as big as its largest case needs, padded to its alignment, the largest of an INT‘s and its fields’. variant a(x: U8); b(y: I64; z: U8); end is 24 bytes on x86-64. A variant that starts at zero therefore holds its first case.

5.7 Enumerations and sets

type
    Color* = (red, green, blue);
    Colors* = set of Color;

An enumeration is a list of names, in order. Like the cases of a variant, the names are declared in the scope around the type. An enumeration has at most 256 names and takes 1 byte; the first name is 0, the next 1, and so on.

A name of an enumeration may also be written with its type, Color.red, and one imported with the type’s module, M.Color.red. Two enumerations of a scope may share a name, and an enumeration may have a name that something else of its scope has, a constant, a variable or a procedure: such a name is written with its type, Elem.bold. Written alone, it names the one declaration of it that isn’t an enumeration’s, if there is one, and is an error if there isn’t:

type
    Style = (bold, italic);
    Elem = (para, bold, rule);
proc rule;                  (* a procedure, beside Elem's rule *)
...
s := Style.bold;  e := Elem.bold;  e := Elem.rule;
e := para;                  (* para is Elem's alone *)
rule;                       (* the procedure *)
s := bold;                  (* an error: write Style.bold or Elem.bold *)

The type is never taken from where the name stands: s := bold is an error though s is a Style.

set of E, for an enumeration E of at most 64 names, holds any choice of E’s names: bit i stands for the name at position i. It takes the smallest of 1, 2, 4 and 8 bytes that has a bit for each name, so a set can stand for a C flags word.

5.8 Errors

const NotFound*: ERROR = "not found";

An ERROR is how a procedure says it failed: by convention the last of its results, and nil when nothing failed. A caller that can’t deal with a failure itself passes it on with try (section 7.8).

ERROR is a basic type as big as an address. A value of it is made only by a constant declared as above, and each such declaration makes an error different from every other, whatever its message: two modules that both declare "not found" have two different errors. A generic module makes its errors once per instance. nil is no error. Only a string makes a new error: an ERROR constant whose value is another ERROR constant is that same error, so const Short*: ERROR = PictBase.Short; passes on an error of another module, and Short = PictBase.Short holds.

Errors compare with = and # only, by which declaration made them, never by their message. MSG(e) is the message, a []const U8; MSG(nil) is "".

proc find*(key: I64): (^Node, ERROR);
...
n, err := Table.find(7);
if err = Table.NotFound then ... end;

5.9 Procedure types

type Compare = proc(a, b: I64): BOOL;

A value of a procedure type is the address of a procedure with that signature, as big as an address, or nil. Two signatures are alike when their parameters have the same types, each var, const or neither alike, in order, and their results are the same types; the parameters’ names don’t matter.

A parameter or a result of a procedure type in a type section may name a type declared later in it, a record that is being declared too:

type Lines = record each: proc(var r: Lines; s: []U8); n: INT; end;

A procedure value is an address whatever its signature, so the record’s size doesn’t depend on it; the type is whole when a call is made. A field of the record’s own type, by value, is still an error, since nothing would be big enough.

5.10 Same and assignable

Two named types are the same only if they are the same declaration. Two anonymous pointer, array, slice, set or procedure types are the same if they are built alike: ^I64 is ^I64 wherever it is written. A record, variant or enumeration, though, is a type of its own wherever it is written, named or not: two record x: I64; end are two types. A named and an anonymous type are the same if the named one is built like the anonymous one, so that p := SYSTEM.ADR(n) works for p: NodePtr with type NodePtr = ^Node. Sameness doesn’t pass through the anonymous type: with type P1 = ^Node; P2 = ^Node;, each of P1 and P2 is the same as ^Node, but they are two declarations, so not the same as each other.

A type declared with only a name on the right, type Count = I64;, is another name for that type, not a new one.

A value of type A can be assigned to a variable of type B (and passed to a parameter of type B, and returned as a B) if they are the same type, or if:

  • A is an integer constant whose value fits in the integer type B;
  • A is nil and B is a pointer, procedure or ERROR type;
  • A is ^T and B is ^VOLATILE T;
  • A is [n]T and B is []T or []const T, or A is []T and B is []const T;
  • A is a string literal and B is []const U8, [n]U8 with n at least the string’s length (the rest is zero), or, in a module that imports SYSTEM, ^U8 (a pointer to the bytes followed by a zero byte, as C wants);
  • A is a procedure and B a procedure type with the same signature;
  • A is INT and B is I64, or A is UINT and B is U64, which loses nothing on any target;
  • A is U8, I8 or I16 and B is INT, or A is U8 or U16 and B is UINT, which an INT or a UINT of 16 bits holds whole, so on every target; unless the value is what an operator gives (below).

A string’s bytes are constant. A string literal, or a slice of a string constant, is a []const U8, so writing them is an error. A [n]U8 made from a string is a copy, the program’s to change. A ^U8 made from one, for C, points at the constant bytes, and writing through it isn’t defined (section 10).

Nothing else converts silently. In particular, there is no other conversion between integer types, between integers and reals, or between F32 and F64, without a written conversion (section 6.7). An INT widens to I64, and a UINT to U64, wherever its value goes where an I64 is wanted: in a, b := f(x) and return f(x) as in any other assignment, to the bounds of a for and the step of INC and DEC whose variable is an I64, and in an expression, where it meets an I64 (section 6.1). The types themselves stay two: a ^INT isn’t a ^I64, an INT variable isn’t passed to a var parameter of type I64, and a procedure returning an INT isn’t of a procedure type returning an I64.

A U8, I8 or I16 widens to INT, and a U8 or U16 to UINT, in the same places, as an INT to I64: assigned, passed, returned, in a, b := f(x), to a for’s bounds and INC and DEC’s step, and in an expression, where it meets an INT or a UINT (section 6.1); not in return f(x), which passes f’s results on as they are. They widen only that far: a U8 meets an I64 only as INT(b) or I64(b). And they widen only as values that are moved: a variable, an element, a field, a call’s result or a conversion’s. What an operator gives on them doesn’t: it was computed in their type, and has wrapped there. With a, b: U8 holding 200 and 100, a + b is 44, so n := a + b, for an INT n, is an error; n := INT(a) + b is 300, and says where the sum is made.

var s: []U8; n, d: INT;
n := s[i];                  (* an element: widens *)
n := n * 10 + s[i] - '0';   (* n * 10 + s[i] is an INT, and so the rest *)
d := s[i] - '0';            (* an error: a U8, which may have wrapped *)
d := INT(s[i]) - '0';       (* below '0' too, it is negative *)

6. Expressions

Expr       = Conjunct { "or" Conjunct } .
Conjunct   = Relation { "and" Relation } .
Relation   = SimpleExpr [ RelOp SimpleExpr ] .
RelOp      = "=" | "#" | "<" | "<=" | ">" | ">=" | "in" .
SimpleExpr = [ "-" ] Term { AddOp Term } .
AddOp      = "+" | "-" | "|" | "xor" .
Term       = Factor { MulOp Factor } .
MulOp      = "*" | "/" | "div" | "mod" | "&" | "shl" | "shr" .
Factor     = number | char | string | Designator | "(" Expr ")"
           | "not" Factor | "~" Factor
           | "[" [ Expr { "," Expr } ] "]"
           | "{" [ Element { "," Element } ] "}"
           | "^" [ "VOLATILE" ] Type "(" Expr ")"
           | "try" Designator .
Element    = Expr | ident ":" Expr .
Designator = QualIdent { Selector } .
Selector   = "." ident | "^" | "[" Expr [ ".." Expr ] "]"
           | "(" [ Expr { "," Expr } ] ")" | "." "(" Type ")" .

The operators bind in the order of the grammar: not, ~ and try (section 7.8) most tightly, then the multiplying operators, then the adding ones, then the relations, then and, then or. So a + b * c = d is (a + (b * c)) = d, x & 0FH = 0 is (x & 0FH) = 0, and i < n and a[i] # 0 or done is ((i < n) and (a[i] # 0)) or done. A unary minus applies to the first term: -a * b is -(a * b).

and, or and not are for BOOLs only; &, |, xor and ~ are for integers only.

A pointer to a record isn’t the record: its fields are p^.f, never p.f, and the elements of a pointer to an array are p^[i]. A statement starts with a name or try, so ^T(x)^ := v isn’t one; a view, mem[a].(I64) := v (section 6.9), says it without a pointer.

6.1 Integers

Both operands of + - * div mod & | xor, and of a relation, have the same integer type, or one is an untyped constant that takes the other’s type, which it must fit, or one is an INT and the other an I64 (a UINT and a U64), and the INT widens to I64, or one is an INT and the other a U8, I8 or I16 (a UINT and a U8 or U16) that no operator gave, and it widens to INT (section 5.10). So do v and k in INC(v, k) and DEC(v, k), where only k widens: an I64 k isn’t added to an INT v. The result has that type and wraps around at its width: in U8, 200 + 100 is 44. A unary minus wraps too: for x of an unsigned type, -x is 0 - x. Other integer types are never mixed, whatever their sizes: with i: I32, i < LEN(s) is an error, and i should be an INT; with c: U8, c < LEN(s) is an INT comparison. With pos: I64, pos + LEN(s) is an I64.

Where the report asks for an integer and names no type, as an index, a slice’s bound, a shift’s count, a pointer’s offset i in p + i, or a conversion’s operand, any integer type will do, and its value is taken. On a target whose INT is narrower, a pointer’s offset is cut to an INT.

SIZE(T), SIZE(T.f), OFFSET(T, f), and LEN of an array or a string constant, are untyped constants, like a literal.

div rounds toward zero and mod takes the sign of the dividend, as in C: -7 div 2 is -3, -7 mod 2 is -1. Dividing by zero, and dividing the smallest value of a signed type by -1, stop the program (section 10), whatever the type and the target.

& (and), | (or), xor and ~ (not) work on every bit. x shl n and x shr n shift by n modulo the width of x’s type, in bits: for x: U8, x shl 9 is x shl 1. shr brings in copies of the sign bit for signed types and zeros for unsigned ones. n may be of any integer type. The result has x’s type, cut to its width: in U8, 0C0H shl 1 is 80H. If x is an untyped constant, so is the result, and it doesn’t wrap: 1 shl 9 is 512, which doesn’t fit a U8.

ROL(x, n) and ROR(x, n) (section 6.8) rotate x left and right by n bits modulo its width: the bits shifted out at one end come back in at the other. For x: U8 holding 81H, ROL(x, 1) is 03H and ROR(x, 1) is 0C0H. x is of an unsigned integer type, U8, U16, U32, U64 or UINT, and the result has its type; n may be of any integer type. An untyped constant has no width, so ROL(1, 3) is an error, and ROL(U32(1), 3) is 8. Hashes and ciphers are written with rotations, which machines do in one instruction, and which two shifts and an or say only at more length: ROR(x, 7) is x shr 7 | x shl 25 for a U32 x.

CLZ(x) and CTZ(x) (section 6.8) count the zero bits above the highest one in x and below the lowest one, and POPCOUNT(x) counts its one bits. x is of an unsigned integer type, and the result is an INT; for x: U8, CLZ(x) is 7 when x is 1, and CLZ(x) and CTZ(x) are 8 when x is 0. The width is the type’s, as for ROL; an untyped constant has none, so CLZ(1) is an error, and CLZ(U64(1)) is 63. POPCOUNT(x) may also take a set, and counts its members. MIN(T) and MAX(T) are the smallest and the largest value of the integer type T, untyped constants: MAX(U8) is 255 and MIN(I16) is -32768; MAX(U64) and MAX(UINT), above the largest I64, have their own type, as a hexadecimal number above it has (section 2). Each of the five, given constants, is a constant (section 4).

ABS(x) (section 6.8) is x without its sign, of x’s type, for an integer or a real. For a signed integer it is -x if x < 0, so the smallest value of the type gives itself, as -x does; for an unsigned type it is x. For a real it clears the sign bit: ABS(-0.0) is 0.0, ABS of a NaN is a NaN, and of minus infinity is infinity. Of a constant it is a constant; of an untyped one, an untyped one, ABS(-5) is 5, and a result beyond the I64s, ABS(MIN(I64)), is an error, as for any arithmetic on untyped constants (section 2).

Relations compare as signed or unsigned according to the type.

6.2 Booleans

and and or evaluate their right operand only when it decides the result. not negates, and = and # compare; # is “different”.

6.3 Reals

+ - * / and the relations work on F32 and on F64. Both operands have the same type, or one is a real constant, which takes the other’s type (section 2). The result has that type: F32 arithmetic is done in single precision, rounded at each step as C rounds float. A constant expression of reals is evaluated in double precision, then rounded once to the type it takes.

Relations are IEEE 754’s: a NaN is equal to nothing, itself included, so for a NaN x, x # x is true and every other relation with it is false. Dividing by zero gives an infinity or a NaN; arithmetic on reals never stops the program.

6.4 Pointers

  • p^ is the variable p points at.
  • p + i and p - i, with i an integer, move p by i elements: by i * SIZE(T) bytes for p: ^T.
  • p - q, with both of the same pointer type, is the number of elements between them, an INT.
  • p[i] is (p + i)^. p[lo..hi] is the slice of the hi - lo elements from p + lo. Neither is checked against a length, which a pointer doesn’t have, but a slice of a pointer that runs backwards, hi < lo, is a failed check (section 6.5). A pointer to an array isn’t indexed this way, since a step would be a whole array: its elements are p^[i].
  • Pointers compare with = # < <= > >= as unsigned addresses. Procedure values compare with = and # only.

p + i, p - i, p[i] and p[lo..hi] reach memory no variable of the program names, and are allowed only in a module that imports SYSTEM (section 3). p^, p - q and comparing are allowed in any.

6.5 Arrays and slices

a[i] is an element of an array or slice, and a[lo..hi] is the slice of the elements from lo up to but not including hi. Both are checked: i must be below the length, and 0 <= lo <= hi <= length. A check that fails prints to standard error where it is, as file, line and column, and what failed, with the values involved (index 7 is out of range for a length of 5), and stops the program with status 2. An index or a bound may be of any integer type, and is checked by its value, whatever its type: a negative I8, or a U64 past the length, fails like any other. A module that says check off; (section 3) leaves these checks out of its code.

Literals. [e1, e2, ...] builds an array, and {f: e, g: e, ...} a record, where the type it must have is known: assigned to a variable, passed to a parameter, returned, compared with a value of that type, or an element of a bigger literal. The elements must be assignable to the element type, and an array literal for [n]T has exactly n of them. A record literal names its fields, in any order, each at most once; the fields it leaves out are zero, so {} is the record with every field zero. An array literal used as a slice is a hidden variable of the procedure, and lives as long as its call; the empty one, [], is the empty slice, as a slice variable starts (section 4), and no variable at all.

c := {ch: 'A', attr: 7};
Fmt.print("{} of {}\n", [Fmt.int(n), Fmt.int(m)]);

Arrays and strings compare. Two operands that are each a []T or a [n]T, of the same element type T, are = when they have the same length and the same elements, and # otherwise, where T is an integer type, BOOL, an enumeration, a set or a pointer type. A string literal compares as a []const U8. The comparison is code of its own where it stands, a check of the lengths and then of the bytes, not a call.

Arrays of reals don’t compare this way, since -0.0 = 0.0 and a NaN is equal to nothing, though their bytes say otherwise; nor do arrays of records, variants or procedures, nor records and variants themselves. Write a loop. Ordering strings is the library’s Str.cmp.

6.6 Enumerations and sets

Enumerations compare with all six relations, by position, and an enumeration can be the variable of a for loop and the expression of a match (section 7.4).

{red, blue} is a set, of the set type of its names’ enumeration; {} is the empty set, where the type it must have is known. On two sets of the same type, + is union, * intersection and - difference; = and # compare, and <= and >= are “is a subset of” and “is a superset of”. x in s is true if x, a value of the enumeration, is in the set s.

6.7 Conversions

A type name applied like a procedure converts: I32(x), F64(n), ^Cell(addr). A pointer type written out uses the ^ form of the grammar: ^VOLATILE U32(0FEE00000H).

SYSTEM.SYSCALL exists only on Linux targets. Other systems have no stable system call interface, and their modules call the C library instead (section 9).

NEW(p, a) calls a^.alloc(a, SIZE(T), A), where A is the alignment of T, and zeroes the bytes it gets if they aren’t nil. Mem.Allocator (the library, doc/raz-lib.md) is the one type of the library the language names.

SIZE(T.f) and OFFSET(T, f) ask about a type’s field, not about storage, so SIZE still takes no variable. f is one field name: not a path, a.b, and not a case of a variant, whose cases share their place. A record handed to C is checked against C’s struct with them, as C checks one with offsetof and sizeof.

n := Sys.write(fd, BYTES(samples));     (* samples: []I32 *)
n := Sys.read(fd, BYTES(h));             (* fills h: Header, a record *)

T must be a type a view may take (section 6.9), since writing through the slice must not make a value mean nothing: a BOOL, a set, an enumeration, a slice, a variant, a procedure type, ERROR, or a record or array holding one, is an error; and, outside a module that imports SYSTEM, so is a pointer, or a record or array holding one. The slice is made, and checked, as any slice of the variable is, so its bytes follow the rules for it: the bytes of a local can’t be returned (section 7.3). Of a slice they are its elements, as SYSTEM.PTR(s) gives them, whatever holds the slice, and can be written only if the slice can. Of any other variable they are its own, as SYSTEM.ADR gives them: a const parameter, another module’s variable, a view and a field of a packed record are errors, as they are for SYSTEM.ADR, and so is a volatile variable. x must be a variable: a constant, a string constant too, is an error. The bytes are in the target’s order (appendix A).

SYSTEM.PTR(s) is the first of the two words of s (section 5.3), and is not checked. For a slice that isn’t empty it is SYSTEM.ADR(s[0]); for an empty one, where s[0] would stop the program, it is what the slice holds: nil for a slice variable as it starts (section 4) and for [], and for one cut empty from another, t[3..3], an address that mustn’t be read through, as the end of an array mustn’t. So a slice becomes a pointer and a length, for a record or for C, with no test for the empty one first:

type Value = record n: INT; p: ^U8; end;

proc valueOf(s: []const U8): Value;
begin
    return {n: LEN(s), p: SYSTEM.PTR(s)};      (* "" too *)
end;

and v.p[0..v.n] is the slice again (section 6.4), empty when v.n is 0, whatever v.p is. Reading through the pointer is as unchecked as through any pointer. SYSTEM.PTR(a) of an array may be taken wherever the slice a[0..LEN(a)] may be made, and is an error wherever it may not.

COPY is a statement, as INC is. It copies the bytes of LEN(s) elements as one block, as an assignment of an array does, and is right when d and s overlap, as in COPY(a[1..n], a[0..n - 1]). It is checked as a slice is: past LEN(d), it stops the program, unless the module says check off;.

FILL is a statement too. d is written as COPY’s destination is, and x is assigned to each element as by :=:

FILL(row[a..b], U32(bg));    (* a row of pixels *)
FILL(window, 0.0);           (* window: [576]F32 *)

It is no wipe: it may be left out when nothing reads what it wrote, as any write may (section 7.6).

INC and DEC evaluate v once, so INC(a[f(i)]) calls f once. They read v and then write it: two accesses, even through a ^VOLATILE pointer, and not atomic; XADD is the atomic one.

For CAS, XCHG and XADD, v is a variable, as for INC, of type INT, UINT or a pointer type (INT or UINT for XADD), on every target, and may be volatile: a counter shared between threads is XADD(count, 1), one reached through a pointer XADD(p^, 1). It is evaluated once, and must have an address, so a field of a packed record and a view are errors, as they are for SYSTEM.ADR. They are sequentially consistent, on every target; how a machine without atomic instructions makes them so is the implementation’s choice (appendix A). ### 6.9 Views

A view reads and writes the bytes of a variable as a value of another type. v.(T), with v a variable, is the T whose bytes start where v starts:

var mem: [4096]U8; n: I64; x: F64; bits: U64;

mem[16].(I64) := -1;     (* the 8 bytes mem[16] to mem[23] now hold -1 *)
n := mem[16].(I64);      (* and are read back as an I64: n is -1 *)
bits := x.(U64);         (* the 8 bytes of x, as a U64 *)

A view is a variable, not a value: mem[16].(I64) is made of the 8 bytes mem[16] to mem[23], as p^ is the variable p points at. Reading it reads those bytes; assigning it writes them, and so changes mem. Nothing is copied to make it. It stands wherever a variable may: on the left of :=, as the variable of INC, and with selectors after it:

type Header = record magic: U32; count: U32; end;
var buf: [512]U8; k: U32;

k := buf[0].(Header).count;    (* bytes 4 to 7 of buf, as a U32 *)
buf[0].(Header).count := 0;
INC(mem[a].(I64), 8);

A view isn’t a conversion. A conversion works on a value, a view on bytes. With x: F64 holding 1.5, I64(x) is 1, the number rounded toward zero, while x.(I64) is 3FF8000000000000H, the bits that hold 1.5. With n: I64 holding 258, U8(n) is 2, the number cut to its low byte, while n.(U8) is the first byte of n in memory, which is the low one only on a target that puts its low byte first (appendix A). When the program means a number, it wants a conversion; when it means the bytes as they lie, a view.

The types. T is an integer type, a real type, a pointer type, or a record or array made of these alone, at any depth: the types for which any bytes at all are a value. BOOL, an enumeration, a set, a slice, a variant, a procedure type and ERROR are left out, since bytes that are none of their values would make the program mean nothing. To read one of them from bytes, view the integer and convert it: Colour(mem[a]). v may be of any type, and is a variable: a name of one, a field or element of one, or what a pointer points at; not a constant, nor the result of a call or of an operator.

A view makes values from bytes, so where those bytes could be made into an address the module must import SYSTEM (section 3): a view whose T holds a pointer, and a view written over a variable v whose type holds anything but integers and reals, which would change a pointer, a BOOL or a slice behind its type. Reading any variable through a view of integers and reals is allowed in any module.

Where its bytes lie. The T lies within the variable v is part of:

  • for an element of an array or a slice, a[i].(T), from that element to the end of a: mem[4088].(I64) is the last 8 bytes of mem, and mem[4090].(I64) would run 2 bytes past its end;
  • for anything else, within v itself: x.(U64) is allowed only if x has at least 8 bytes.

This is checked, as an index is: by the compiler when it can tell, otherwise while the program runs, where a view that runs past the end is a failed check (section 6.5), unless the module says check off;. An element reached through a pointer, p[i].(T), is checked no more than p[i] is, since a pointer has no length.

Any address. The T may start at any byte: mem[3].(I64) is an I64 whose first byte is mem[3]. As a field of a packed record is (section 5.5), it is read and written on every target, in parts where the machine needs that; and, as such a field, a view has no address: SYSTEM.ADR of it, a var argument of it and a slice of it are errors. Copy it out to a variable, and back in. A view of a volatile variable is an error too, since its access can’t be promised as one (section 7.6): a device’s registers are reached through a ^VOLATILE pointer to a record of them.

Byte order. The bytes are in the target’s order (appendix A). A file or a message whose format fixes an order of its own is read with Str.le, Str.be and the like (section 5.5), if the program is to read it right on every target.

Before views. A program used to make a pointer for each access, and may still: mem[a].(I64) := n does what

p := ^I64(SYSTEM.ADR(mem[a]));
p^ := n;

does, but with a checked against the length of mem, no pointer variable, and no address of a word that may be misaligned, and no import SYSTEM.

v is evaluated once, and its check made, before the bytes are read or written.

7. Statements

Statements = { Statement ";" } .
Statement  = Designator [ ":=" Expr ]
           | "_" ":=" Expr
           | Target "," Target { "," Target } ":=" Expr
           | "if" Expr "then" Statements
             { "elsif" Expr "then" Statements } [ "else" Statements ] "end"
           | "while" Expr "do" Statements "end"
           | "repeat" Statements "until" Expr
           | "for" ident ":=" Expr "to" Expr [ "by" Expr ] "do" Statements "end"
           | "match" Expr "of" { "|" Arm } "end"
           | "return" [ Expr { "," Expr } ]
           | "break"
           | "continue"
           | "defer" Statement
           | "try" Designator .
Arm        = ( ident { "." ident } [ "(" ident { "," ident } ")" ]
             | Label { "," Label } | "else" ) ":" Statements .

Target     = Designator | "_" .

Every statement ends in ;, including the ones that end in end or until.

7.1 Assignment and calls

x := e evaluates e and stores it in x; arrays, records, slices and variants are copied. A designator on its own is a call, and any result it returns is dropped: Out.ln;, write(fd, buf);.

a, b := f(x); assigns the results of a procedure that returns several (section 8), in order.

The blank, _, drops what would be assigned to it: _ := e; evaluates e and drops it, and n, _ := f(x); keeps the first result and drops the second. What is dropped is still evaluated as any expression is: its calls are made, and a volatile variable in it is read (section 7.6). A result dropped by a call standing on its own is a lint an implementation may warn of (section 10); one dropped through _ says it is meant.

7.2 Conditions and loops

if, while and repeat take BOOL expressions. repeat runs its body at least once and stops when the condition is true.

for i := a to b by s do ... end; sets i to a, a + s, … while i <= b (or i >= b if s is negative). i is a variable of an integer or enumeration type, named by its name alone; a and then b are evaluated once, before the first round; s is a constant other than zero, and 1 if left out. a and b have i’s type, or are untyped constants that take it, or are INTs that widen to an I64 i, as with + (section 6.1): so in for i := 0 to LEN(s) - 1, i is an INT or an I64.

The loop never steps past b, so i can’t wrap: afterwards i holds the last value it took, or a if the body never ran. The body may assign i. Precisely, for a positive s: at the end of a round, if i <= b and b - i < s, the loop ends with i as it is; otherwise i becomes i + s, wrapping, and the loop goes on while i <= b. A negative s is the same, the other way round.

break ends the innermost while, repeat or for it stands in, and the program goes on after it. continue ends the round of the innermost one, as reaching the end of its body would: a while tests its condition again, a repeat tests its until, and a for steps its variable, or ends. There is no goto.

A continue passes over the rest of the body, the step of a while or a repeat included, if it stands there: so the step comes first.

while i < LEN(t) do
    ch, n := Str.decode(t[i..LEN(t)]);
    i := i + n;                         (* before any continue *)
    if ch = 0ADH then continue; end;    (* a soft hyphen, passed over *)
    ...
end;

7.3 Return

return e; ends the procedure with the result e; return a, b; with several results; return f(x); with the several results of f, if they are the procedure’s own (section 8); return; from a procedure without results. A procedure with results that runs off its end returns zeros, each result as a variable of its type starts (section 4).

A slice returned must not point into the procedure’s own frame, which is gone once it returns. It is an error to return, as a slice, a local array, a value parameter that is an array, an array literal other than [], or an array a call returns, or a slice of one, or the BYTES of a local variable, a field or an element of one included:

proc short(h: Hex): []U8;      (* Hex = [64]U8 *)
begin
    return h[0..8];            (* an error: h is the procedure's copy *)
end;

A slice of a var or const parameter, of a module variable, or of what a pointer points at may be returned: none of them is this procedure’s frame. For a const parameter given a temporary, the slice lives to the end of the caller’s procedure (section 8). A slice of a frame that leaves it some other way isn’t caught, and is the exception of section 10: one held in a local slice variable, or in a record, that is returned; one stored in a module variable or through a pointer; and one that came back from a call, as the slice of a var parameter does to the caller whose local it is.

7.4 Match

match s of
| circle(r):  area := 3.14159 * r * r;
| rect(w, h): area := w * h;
| dot:        area := 0.0;
end;

match takes a variant, an enumeration, an integer type (a U8 included) or a string, a []U8 or a []const U8; other types are an error. It runs the arm of the case s holds. An arm may name the case’s fields, in order, all of them; the names stand for those fields of s itself, so assigning to one changes s; if s is a constant or a const parameter, they can’t be assigned; if s isn’t a variable, they stand for the fields of a copy. An arm may also leave the fields unnamed. Every case must have an arm, and only one, unless there is an | else: arm, which must come last.

match on an enumeration works the same way: each arm names one of the enumeration’s names, or several, separated by commas, for the arm to run when the value is any of them:

match op of
| sPlus, sMinus: kind := additive;
| sTimes:        kind := multiplicative;
| else:
end;

Every name must have an arm, and only one, unless there is an | else: arm. A variant’s arm names one case: the fields it may name belong to that case alone.

An arm on an enumeration or a variant names its case alone or as it is written anywhere else, with its type, its module, or both (done, Kind.done, Xml.done, Xml.Kind.done), and a qualified name must be a case of the matched type.

match on an integer runs the arm whose labels hold its value:

match ch of
| ' ', '\t':      skip := true;
| '0' .. '9':     digit := true;
| else:
end;

A label is a constant, or lo .. hi, the constants from lo to hi, both included (unlike a slice, which leaves hi out; lo may not be above hi). Each must fit the integer’s type, and no value may be in two labels. An integer match must have an | else: arm, which may be empty.

match on a string, a []U8, a []const U8 or what converts to one (section 5.10), runs the arm one of whose labels it equals, as = compares strings (section 6.5):

match word of
| "add", "plus": op := add;
| "sub":         op := sub;
| else:          op := none;
end;

A label is a string constant, and no two labels may be equal; there are no ranges. A match on a string must have an | else: arm, which may be empty. Whether an arm names a case or gives labels is set by the type matched: | Max: is a case of a variant or an enumeration, and a constant for an integer or a string.

7.5 Order of evaluation

Operands, arguments and the designators of an assignment are evaluated from left to right, and the designators of an assignment before its right side: a[i()] := g() calls i and then g.

7.6 Volatile

A variable reached through a ^VOLATILE T is volatile, and so is any field or element of it. Each read or write of a volatile variable of a basic, enumeration, set or pointer type is exactly one memory access, of exactly its size, and volatile accesses happen in the order the program writes them. Copying a whole record or array through a volatile pointer is not allowed, since it can’t be one access.

A ^VOLATILE T doesn’t convert to ^T without a written conversion, and a volatile variable isn’t passed as a var argument, which would lose its volatility.

FENCE also orders the program’s ordinary accesses against those of other processors and devices.

Ordinary variables. Only volatile accesses, CAS, XCHG, XADD and FENCE are exact. Any other access is ordinary: an implementation may keep a variable in a register, leave out a write that nothing reads, and change the order of ordinary accesses, as long as each thread, on its own, does what this report says. A variable that one thread writes while another reads or writes it, unless both use volatile accesses or the atomic built-ins, or a FENCE orders them, holds no particular value then: a read of it gives a value it had or was given, or a mixture of their bytes. For a variable of a basic, enumeration or set type, or a record or array of these, nothing else of the program becomes undefined by it. For one that holds a pointer, a procedure, a slice, an ERROR or a variant, a mixture may be an address no variable has, or a slice’s address with another’s length, or a case’s tag with another’s fields, and what follows isn’t defined (section 10). A program that shares such a variable between threads orders their accesses, with a lock or the atomic built-ins.

7.7 Defer

defer s; runs the statement s when the program leaves the statement list the defer stands in: at its end, or by a return, or by a break or continue out of it. Statements deferred in the same list run in the opposite order to their defers, and only those whose defer has been reached run.

module Head;
import Sys, Out;

(* Prints the first line of the file at path. *)
proc head(path: []const U8): BOOL;
var fd, n, i: INT; buf: [256]U8;
begin
    fd := Sys.openRead(path);
    if fd < 0 then return false; end;
    defer Sys.close(fd);
    n := Sys.read(fd, buf);
    if n < 0 then return false; end;
    for i := 0 to n - 1 do
        if buf[i] = 10 then n := i; break; end;
    end;
    Out.str(buf[0..n]);
    Out.ln;
    return true;
end;

proc main*;
begin
    if not head("/etc/hostname") then Out.str("no hostname\n"); end;
end;

end Head.

return e; evaluates e before the deferred statements run. A deferred statement can’t contain defer, nor a return, break, continue or try that would leave it. A failed check, Rt.exit and Sys.exit end the program without running the deferred statements still pending.

7.8 Try

A procedure that can fail returns an ERROR as its last result (section 5.8), nil when it didn’t. A caller that can’t deal with the failure passes it on to its own caller, which try does in a word:

proc total(words: [][]U8): (INT, ERROR);
var i, sum: INT;
begin
    for i := 0 to LEN(words) - 1 do
        sum := sum + try number(words[i]);
    end;
    return sum, nil;
end;

try c, where c is a call (below) of a procedure whose last result is an ERROR, makes the call and looks at that error. If it is nil, the program goes on, and try c is what c returned without the error. If it isn’t, the procedure try stands in returns at once, as return does (section 7.3): its last result is that error, and every other result is zero, as a variable of its type starts (section 4). Nothing more of the statement try stands in is done; in the example, sum isn’t assigned. So

x := try f(a);

is, with e a variable the program can’t name, and 0 standing for a zero of each of the procedure’s other results:

x, e := f(a);
if e # nil then return 0, e; end;

The error is the one c returned, and compares with = as it did there. try has no handler and keeps no state: it is a return, written where the call is, so that every place a procedure can leave is in its text. A program that means to deal with an error tests it, as section 5.8 shows.

What try is applied to. c is a designator that ends in a call: f(x), Mod.f(x), p^.next(x), or a call through a variable of procedure type. Where the procedure has no parameters its parentheses may be left out, as in a statement (section 7.1), and try calls it: try setup;. A conversion, a built-in procedure (section 6.8) and the case of a variant are written like calls and aren’t procedures’; try can’t be applied to them.

What try c is. c’s results but the last.

  • With none, try c isn’t a value and stands only as a statement: try flush;.
  • With one, it is a value of that type, an operand wherever c would be: n := try number(s);, sum + try number(s), if try ready(fd) then. Like not, it applies to the factor after it: try f(x) + 1 is (try f(x)) + 1.
  • With several, it stands only on the right of a multiple assignment, as c itself would, with a target for each: a, b := try f(x);.

As a statement, try c; drops the values of c that it has, and a dropped value is a lint, as a call that drops a result is (section 10); _ := try c; and a, _ := try c; say it is meant (section 7.1). The error is never dropped: try is the way of passing it on.

Where try may stand. Every use of try is an error unless:

  • the procedure it stands in has an ERROR as its last result. A module’s body, and a procedure with no results, such as proc main*;, have none: there an error is dealt with where it is found, by a test;
  • the last result of the procedure c calls is an ERROR;
  • it is not inside a deferred statement, which try would leave (section 7.7).

A generic module is checked in each instance (section 3), so a procedure of an instance whose last result, by its type arguments, is no ERROR and uses try is an error in that instance.

Order. The arguments of c are evaluated from left to right, then c is called, and then its error is looked at (section 7.5). The designators on the left of an assignment are evaluated before its right side as always, so in a[i()] := try g(), i is called, then g; if g fails, nothing is assigned. A try in the right operand of and or or is reached only when that operand is evaluated (section 6.2).

Deferred statements. When try returns, the statements deferred in the procedure and not yet run are run, the last first, as for a return (section 7.7), after the error and the zero results have been chosen; no deferred statement can change them.

8. Procedures

ProcDeclaration   = "proc" IdentDef Signature ";"
                    ( "forward" | { LocalDeclaration } "begin" Statements "end" [ ident ]
                    | "code" { [ ident ":" ] [ Instruction ] ";" } "end" [ ident ] ) .
LocalDeclaration  = "const" { ident [ ":" Type ] "=" Expr ";" }
                  | "type" { ident "=" Type ";" }
                  | "var" { ident { "," ident } ":" Type ";" } .
Signature         = "(" [ Params { ";" Params } [ ";" "..." ] ] ")" [ ":" Results ]
                  | [ ":" Results ] .
Params            = [ "var" | "const" ] ident { "," ident } ":" Type .
Results           = Type | "(" Type { "," Type } ")" .

A procedure without parameters may leave out the parentheses, both where it is declared (proc main*;) and where it is called (Out.ln). Used without parentheses in an expression, a procedure is a procedure value, not a call.

Parameters. A value parameter is a copy: the procedure may change it, and the caller’s variable stays as it was. A var parameter is the caller’s variable itself; its argument must be a variable of exactly the parameter’s type.

A const parameter is the caller’s variable too, read in place, whatever its size, with nothing copied; the procedure may only read it. It may not assign it or a part of it (a field, an element of an array in it), give it or a part of it to a var parameter, take the SYSTEM.ADR of either, write it through a view (section 6.9), or assign the names a match arm gives its fields. What a slice or a pointer in it points at isn’t part of it: the procedure may write through them, as it may through a value parameter’s; but a slice it makes of an array in it is a []const T (section 5.3), so it can’t write the caller’s array through it. const keeps the procedure from changing the variable, not what its slices and pointers point at. Its argument is any expression of the parameter’s type: a variable or a constant is passed in place, anything else as a temporary, of the procedure if it holds an array, as an array a call returns is (below). If the variable changes while the procedure runs, through a var parameter, a pointer or another thread, the procedure sees the change.

type Parser = record args: [][]U8; at: INT; (* ... *) end;

proc current(const p: Parser): []U8;     (* reads p, many words, in place *)
begin
    return p.args[p.at];
end;

proc advance(var p: Parser);             (* changes p *)
begin
    INC(p.at);
end;

A procedure takes what it reads as a value when it is a single value or a slice, and as const when it is a record or an array; what it changes, as var; and a pointer only for what it keeps past the call, what may be nil, an allocator, or what C or the system takes.

Results. A procedure returns nothing, one value, or several. A call that returns several values can only stand on the right of a multiple assignment, alone as a statement, or alone after return in a procedure whose results are of the same types, in the same order, which then returns them as they are: return divmod(n, 2);. A procedure that can fail has an ERROR as its last result (section 5.8), which try passes on (section 7.8).

An array a call returns, or a record or variant holding one, is a hidden variable of the procedure the call is in, as an array literal used as a slice is (section 6.5), and lives to the end of that procedure’s call. A slice of it may be kept in a variable and used for the rest of the procedure; in a loop, the hidden variable holds what the latest call returned. Like any slice of the frame, it may not be returned (section 7.3):

s := f('a')[0..4];     (* f returns a [8]U8: s is good to the end of the procedure *)
t := f('b')[0..4];     (* a hidden variable of its own: s is unchanged *)
module Divide;
import Out;

proc divmod(a, b: I64): (I64, I64);
begin
    return a div b, a mod b;
end;

proc main*;
var q, r: I64;
begin
    q, r := divmod(17, 5);
    Out.int(q); Out.str(" rest "); Out.int(r); Out.ln;
end;

end Divide.

forward. proc f(x: I64): I64; forward; declares f so that it can be called before its body appears; the body comes later in the module, with the same signature, though its parameters may have other names; a forward with no body is an error.

A name after a procedure’s end, if written, is the procedure’s own.

Procedures don’t nest.

Code procedures. A procedure whose body is code is machine code, written by hand in the target’s assembly language (appendix A), in a module that imports SYSTEM: one instruction to each ;, and labels for jumps, up to end:

proc rdtsc*: U64;
code
    rdtsc;
    shl rdx, 32;
    or rax, rdx;
    ret;
end rdtsc;

A label, name:, names the place of the instruction after it, within the procedure. A constant of the module may stand wherever a number does. A procedure or a global variable of the module, or one an imported module exports, by its qualified name, stands for its address in three places only: call p; and jmp p;, which reach it from where they are, and lea r, [v];, which puts its address in a register. A label of the procedure is found first. Nothing of its type is checked, and no other operand takes one. What is named is part of the program, as a procedure that is called is. Any bytes may be written with db, as in db 0FH, 31H;, for an instruction the assembler doesn’t know.

It is called like any procedure, with the System V convention: integer and pointer arguments, and the addresses of var and const ones, arrive in rdi, rsi, rdx, rcx, r8 and r9, F32 and F64 ones in xmm0 to xmm7, and the result goes in rax (and rdx for a second) or xmm0. Its parameters and results are therefore of the types C can take (section 9), or slices, at most six integer and eight real parameters, and at most two results. A slice is two integers, as System V passes a struct of them: as a parameter its address arrives in one register and its length in the next, the two counting among the six; as the result its address goes in rax and its length in rdx, and it is the only result. The instructions are the whole procedure, ret included; they must keep rbx, rbp, rsp and r12 to r15 as they found them. The compiler doesn’t look past what they say.

9. Calling C

ExternDeclaration = "extern" ( "proc" IdentDef Signature
                             | "var" IdentDef ":" Type ) .
link "libX11.so.6";
extern proc XOpenDisplay(name: ^U8): ^U8;
extern proc printf(format: ^U8; ...): I32;
extern var environ: ^^U8;

An extern procedure or variable is found by its name in the C libraries the program links, and is declared only in a module that imports SYSTEM (section 3), since C can reach any memory: the C library always, and each library named by link.

An extern procedure’s parameters and result are integers, BOOL, F32, F64, pointers or procedures; a record goes to C by pointer, never by value. ... accepts any number of further arguments of those types, and is allowed only in an extern. C takes no float there, so an F32 given to ... is an error: the program writes F64(x). Past the parameters, a real constant goes as an F64, an integer constant as an INT, and a string literal as a pointer to its bytes followed by a zero byte.

An extern variable is C’s variable itself: reading it reads C’s, assigning it writes C’s. It can be of any type, declared as C declares it, a record laid out as C lays it out (section 5.5); the compiler can’t check that it is. A C variable that is local to each thread, such as errno, can’t be reached this way; the C library has a procedure for it (__errno_location).

A C union has no raz type. A program reads one as an array of words, and the member it wants through a pointer conversion:

var ev: [24]I64;                       (* XEvent: 192 bytes *)
...
XNextEvent(dpy, SYSTEM.ADR(ev));
if I32(ev[0]) = KeyPress then
    key := ^XKeyEvent(SYSTEM.ADR(ev));
    ...
end;

Every raz procedure uses the System V calling convention, so a raz procedure whose parameters and result are of those types can be given to C as a callback.

10. Programs

Any module may export a procedure main, declared proc main*; or proc main*: INT;. The program runs the bodies of all its modules (section 3), then the main module’s main, if it has one, and ends with status 0, or with the status main returns, by calling Rt.exit. The main of an imported module is an ordinary procedure, which runs only if something calls it; so a library module can carry a main that tests it. A program uses C if any of its modules has an extern declaration or a link of a library; a module’s other files, read only to check its interface (section 3), don’t count. A program that doesn’t is a static executable with no run time besides the code it uses. One that does is linked dynamically and starts through the C library, so that C’s own set-up and clean-up run. A program with a module that says link static; must not use C, and the compiler reports an error if it does.

Ending. Rt.exit(status) ends the program. First it runs the procedures registered with Rt.atExit, the last registered first, each at most once; then it ends the program with status, through C’s exit in a program that uses C, so that C flushes its own buffers. A program that stops (below), a failed check (section 6.5) included, runs them too, after its message, so that Out’s buffer is written out, and ends with status 2. Sys.exit ends the program at once, and a program killed by a signal from outside runs none of them.

proc atExit*(p: proc): ERROR;   (* Rt.Full if 32 are registered *)
proc exit*(status: INT);
proc trace*;                    (* the calls under way, on standard error *)

Rt.trace says on standard error the calls under way, from the one that calls it out, each with its variables, as a program that stops does.

Defined behaviour. Every variable starts at zero, integers wrap, and indexing arrays and slices is checked, so a program’s behaviour is defined by this report, with one exception: memory reached other than through a checked variable. In any module, three things reach it: a pointer used after the memory it points at was given back (by Heap’s free or an arena’s reset, say), a slice kept after the call whose frame holds what it points at (section 7.3), and a race on a variable that holds a pointer, a slice or a variant (section 7.6). In a module that imports SYSTEM, so does what that module does there (section 3): a made-up pointer, indexing through a pointer, an index out of range under check off;, writing a string’s bytes through a ^U8, a code procedure that breaks its rules, and C code. Each can read or write any memory, and what follows isn’t defined. Dereferencing nil, dividing by zero, calling a nil procedure and running out of stack stop the program, on every target, with status 2, as a failed check does. Before it stops, the program prints to standard error where it was, as file, line and column, and why, as far as it can tell: a nil pointer, a nil procedure, a stack overflow, a bad address or a division fault; then the calls under way, each with its variables of a basic, enumeration, set or pointer type. Whether the machine catches these or the compiled code checks for them is the implementation’s choice (appendix A); that they stop the program isn’t.

Separate compilation. An importer depends only on a module’s interface: what it exports, as an importer sees it, never its source or its code. An implementation that compiles modules on its own makes the same program as if every module were compiled together (appendix A).

Errors. A program that breaks a rule of this report that says it is an error isn’t a raz program, and an implementation must reject it: say what is wrong and make no executable. Such a rule is one whose breach would leave the program with no meaning this report can give: a mistake of types, a name that isn’t declared or is declared twice, an assignment to what is read-only, a call with the wrong number of arguments, a type name or a procedure with no result used as a value, type arguments given to a module that isn’t generic, or too many, an import that can’t be found, a procedure declared forward and never defined, a module that imports itself. A fault that is only a lint isn’t an error: a name declared and never used, or a result that a call standing on its own drops (Sys.write(fd, s);, where _ := Sys.write(fd, s); says it is meant). A program with one is valid, and an implementation may warn of it. The text of its messages, how many it reports and which warnings it gives are its own (appendix A).

Limits. An implementation accepts at least: 63 levels of parentheses and calls nested in one expression; 63 levels of statements nested in one procedure; a chain of 15 modules, each importing the next; 31 names declared together (a, b: INT) and 15 variables assigned together (a, b := f()); 1023 elements in one array literal; 255 labels in one match; 31 deferred statements in force in one procedure; and 8 type arguments to a generic module. It may accept more, and its own limits are its own (appendix A); past one, it rejects the program with an error that names the limit, as for any other error, and never fails in another way.

Appendix A. What an implementation chooses

Everything in this report binds every implementation of raz, except what follows, which each chooses for itself and documents. This compiler’s choices are in doc/compiler.md, under “This compiler’s choices”. The programs in conform/ are how an implementation shows that it follows this report: it passes them all, its reals aside where its target has none; conform/check.sh runs them.

  • The target. Which machines and systems it compiles for, and the names of their files (linux-x86_64, section 3); for each, the size of an address, and so of INT, whether it has reals, and which C library a program that uses C is linked against.
  • Separate compilation. Whether modules are compiled on their own, and if so into what: the object file, its format, the form of the code in it, when one is out of date, and how an instance is named so that the program keeps one (section 10). This compiler compiles every module of a program together, and writes no object files.
  • Atomics. How CAS, XCHG and XADD are made sequentially consistent on a machine without atomic instructions (section 6.8): on one with a single processor, by holding off interrupts while they run, for one.
  • The calling convention. On x86-64 Linux it is System V (sections 8 and 9); elsewhere it is the C library’s own, so that extern procedures and callbacks work. How a procedure returns several results, and how its frame is laid out, are the implementation’s.
  • What is the target’s. Code procedures (section 8) hold the target’s machine code, written in its assembly language, and exist only where the implementation says so; SYSTEM.SYSCALL exists only on Linux targets (section 6.8). A record’s layout is the target’s C layout (section 5.5), and the order of a value’s bytes is the target’s (little-endian on x86-64).
  • The assembly language. How a code procedure’s instructions are written (section 8). On x86-64 it is Intel’s syntax, as NASM writes it, destination first. Which instructions it knows is the implementation’s; db gives any others.
  • Sizes in the library. How many bytes Out keeps before it writes them, Sys.outSize (the library volume): 4 KB on Linux, fewer on a small machine.
  • The executable. Its format, and the names and line numbers it carries for a debugger (section 10).
  • How a failure is caught. A nil pointer, a division by zero or a stack overflow may be caught by the machine or by checks in the compiled code; either way the program stops with its message (section 10).
  • Limits. How far past the least of section 10 it goes, and how much stack and memory a compile of a given program needs.
  • Messages and warnings. The text of the compiler’s messages, how many errors it reports before it stops, and which warnings it gives, -Werror included (section 10). That a program that is an error in this report is rejected isn’t free; the words that say so are. So is what a program that fails says on standard error: conformance is judged by a program’s standard output and exit status, never by its standard error.
  • Copies. A procedure’s frame may hold copies of its variables that the program can’t name: registers saved to it, temporaries of its statements, its value parameters, and arrays its calls return. An implementation may leave them where they are when the procedure returns, until the stack is used again. A wipe (section 7.6) reaches only the variables it is given. A secret is best kept in one variable, passed by var or const or by pointer, never by value, and wiped there.
  • The command line. How the compiler is run, its options, and where its library lives (sections 1 and 3).

The core. A target may leave out what the system under it can’t give: Sys past writing, ending the program and getting memory, Thread, link and extern. What it must have, besides the whole language, reals aside, is the core of the library: Rt, Out, Mem, Arena, Lock, Str and Buf, and of Sys what they need. A program that keeps to the core runs on every target. The rest of the library (Heap, Fmt, List, Map, Vec, Sort, Math, Files, Opt, Width, Rand, Check, Prop and the rest of Sys) is the standard library: a target may leave a module out, and one that has it gives what doc/raz-lib.md says. conform/ tests the core only.

NEW(p, a) calls a^.alloc. Heap is the general allocator; Heap.heap gives nil when memory runs out, and Heap.sure stops the program instead, as Buf does, so that NEW(p, Heap.sure) needs no check.

Heap has a debug mode, a light AddressSanitizer, chosen by RAZ_HEAP=debug in the environment or by Heap.debug(true). Normal mode pays nothing for it. In debug mode each block given has 8 guard bytes after its last, and a freed block is filled with 0DEH bytes and held in a quarantine, the last 1,024 frees, before it may be given again. A broken guard, a write past the block’s end, is found when the block is freed; a block that leaves the quarantine with a byte not 0DEH, a write after free, is found then. Either stops the program, saying what was found and the block’s address and size, with the calls under way, and status 2. A big block, which has pages of its own, is not quarantined: its guard is checked and its pages unmapped, so a later use of it faults. debug changes only the blocks given after it, so call it before the first allocation; a block is freed as it was given, in either mode. Only writes are found, not reads, and not those past the guard or after the quarantine. An arena hands out memory from one block: its free does nothing, and reset forgets everything.

Task(T) starts a thread without a cast: import Jobs := Task(Job); t, e := Jobs.spawn(work, job); is the safe form of Thread.spawn(work, ^U8(ADR(job))). spawn copies x into a block from Heap before it returns, so the caller may change or drop its x at once. The thread owns the copy: work changes it freely, and the thread frees it when work returns. The thread is joined with Thread.join; Thread.Failed comes back if there is no memory for the copy or the thread. A result goes back through a pointer in x, read after join.

Guarded(T) is a T with its Thread.Mutex, for sharing a container between threads: the value is reached only through with, which holds the lock while p runs. A zeroed Guarded is ready. p must not call with on the same Guarded, nor keep a pointer into its x.

A Lock is for short sections: a thread that finds it taken tries again, giving up the processor now and then. A Mutex sleeps. Each of Thread’s threads runs on a stack of its own, with a page below it that can’t be touched, so that running off the stack stops the program with a message, as in the main thread. In a program that uses C, Thread makes its threads with C’s pthread_create, so that C’s library knows of them; in one that doesn’t, with the system’s own calls. The program is the same either way.

Sys.kill signals a program, and the system gives the signal to any of its threads; signal gives it to t alone, until t is joined, and is -3 (ESRCH) once t has ended. With Sys.handle(sig), a call t waits in, a read or a ready, fails with -4, so that one thread can break into another’s wait, as ^C breaks into the main thread’s. A signal sent before t begins its wait is only noted, so a program sends it again until t says it has stopped.

info follows a symbolic link: size, dir and file are those of what it names, and symlink says the path was a link, so that a program walking a tree can choose not to follow one back up it. A link to nothing is -ENOENT, as a missing file is. file lets a walk open only what holds data: opening a pipe would wait for a program to write to it.

nextEntry gives every name in the directory except . and .., in no particular order. entryKind says what the name it gave last is, a file, a directory, a symbolic link (whatever it names) or something else, as the directory itself records it, so that a program walking a tree needn’t ask linkInfo of every name, a system call each; where the file system doesn’t record it, it is unknown, and linkInfo must be asked. rawMode turns off what the terminal does with keys before the program reads them (echo, line editing, signals, flow control), and NL to CR NL on output. A program that turns it on restores it before it ends: Rt.atExit is the place.

Files. open gives a file for what how asks: reading, writing or both; creating it if it is missing, readable by all and writable by its owner; with exclusive, failing with -17 (EEXIST) if it is there, as a program does that makes a lock or a file of its own; truncating it to nothing; appending, each write going to its end, however other programs write it too. openMode is open that gives a file it makes the bits mode, less those the umask takes away: 1EDH (755) for a program, 124H (444) for a file never to be written; open gives 1A4H (644). seek moves to pos from the start of the file, or from its end if fromEnd, where a negative pos reads back from the end; position says where the file is, without moving. truncate makes the file size bytes long, cutting it or adding zeros, and leaves the position where it was. sync returns once what was written to the file is on the disk, as a program needs before it says a file is saved; syncAll returns once everything written to the file system that holds the file is on the disk, at once rather than a file at a time, and may flush other file systems too. lock takes the file’s lock for one open file alone: another that asks for it waits if wait, and otherwise fails with -11 (EAGAIN). The lock goes when the file is closed or the program ends, however it ends, so it never goes stale as a file made with exclusive does. lockShared takes it shared, as a program that only reads asks it: any number may hold it so at once, and lock waits, or fails, until the last has let it go, as a shared one waits for the one that lock took. Both are flock’s, so they agree with any other program that takes the file’s lock so. closeChecked closes as close does, and says if that failed: a file system may say only then that what was written never reached it, a full disk or a quota over NFS, so a program that must know its writes landed, as one that copies a backup, asks it. The fd is closed either way, so a failed closeChecked, -4 (EINTR) too, is never tried again. infoOf is info of an open file: its size is what it holds now, however it was written; linkInfo is info of a symbolic link itself, not what it names, so that symlink is true, dir and file false, and size the length of what it names, which need not be there. Info.mtime is what a program checks to see whether a file changed under it, and Info.ino whether it is still the same file, not one renamed over it; 0 on a target whose files have none. Info.dev is the file system the file is on: two files are one only if both dev and ino agree, which is how a program following links finds that one has led it back into a directory it is already in. Info.links is how many names the file has: more than 1 if a hard link shares it, so that writing to it writes to a file named elsewhere too; 0 on a target that doesn’t say. Info.mode holds the nine bits of rwxrwxrwx, and chmod sets them, 1EDH (755) for a program, 1A4H (644) for data; Info.special holds the three above them, set-user-id 800H, set-group-id 400H and sticky 200H, which chmod sets too, with mode | special, as a program that copies a file keeps them. Info.uid and Info.gid are the owner’s and the group’s numbers; chown sets them, with -1 for one to leave as it is, so that a program that saves a file by writing another and renaming it over the first can give it the first’s owner (only root may give a file to another user). makeFifo makes a named pipe, given the bits mode as makeDirMode is; Info of one has file and dir false, and open with nonblocking doesn’t wait for its other end. makeDirMode is makeDir that gives the directory the bits mode, less those the umask takes away, as openMode gives a file: 1C0H (700) for one only its owner may enter. Of the three above them, Linux gives a new directory only sticky; it takes set-group-id from the directory it is made in. setTime sets the file’s time, following a symbolic link, and the time it was last read with it, as a program that copies or restores a file keeps its time, so that a later run sees it unchanged: sec seconds and nsec, from 0 to 999999999, nanoseconds since 1970. Info.mtime holds the time in nanoseconds, which an I64 holds from 1677 to 2262 only; Info.seconds holds it in whole seconds, rounded down, whatever it is, so a program that copies times exactly takes Info.seconds, and the nanoseconds as mtime - seconds * 1000000000, which is right in any year, since the wrapping cancels out (section 6.1).

Programs. openPty makes a pseudo-terminal, a terminal that a program, a terminal emulator, plays the screen and the keyboard of: what it writes to the fd is typed, and what the programs on the terminal write it reads.

spawn starts the program at p.path, with p.args as its arguments, the first being its name. A p.path without a / is looked for as a shell looks for a command, and as C’s execvp does: in each directory of this program’s PATH in turn, an empty one being the working directory, or of /bin:/usr/bin if PATH is unset or empty; the first that runs is the program. If there is none, spawn says so, -2 (ENOENT) or -13 (EACCES), before it makes a child: no program is started, and no process id given for a program that was never there. A p.path with a / is not looked at first, and a program that is there but that the kernel then refuses to run (not a program, a bad interpreter) is a child that ends with status 127. Its environment is this program’s with each NAME=value of p.env added or put in place of the old value, or, if p.onlyEnv, p.env alone. It starts in p.dir. Its standard input, output and error are p.fds; a 0 gives it this program’s own, so {path: "ls", args: ["ls"]} runs ls as a shell runs it, with every other field zero. It gets no other open file but those of p.more, each at its own number, as a shell passes 3<file on, every signal does what it does at first, and none is blocked; with p.keepIgnored, a signal this program ignores stays ignored in it, as the kernel’s execve leaves it, which is what a program run under nohup wants of the programs it starts. If p.tty is a pseudo-terminal’s fd, the program starts a session on that terminal: it is its controlling terminal, and its standard input, output and error, but that a p.fds[i] that is not 0 is that file instead, as for a job that reads /dev/null; p.group is not used.

p.group puts the program in a process group, the programs that a shell’s job is made of: -1 makes it the first of a new group, whose number is its process id, and the other programs of the job join that number. The terminal gives its keys, and the signals of Ctrl-C and Ctrl-Z, to one group, the one in its foreground: p.foreground puts the program’s group there before it starts, and foreground puts any group there, as a shell does to take the terminal back. setGroup moves a program to a group, as the shell does for each program it starts, for whichever of the two runs first; a shell runs in a group of its own, setGroup(0, 0).

exec runs the program p describes in this program’s place, as a shell’s exec cmd does, found and started as spawn would start it, p.tty, p.group, p.foreground, p.fds and p.dir included, except that it keeps this program’s other open files: each stays open in the program unless it is closed on exec, as the files open, pipe, a socket or memFile gives are, unless keepOnExec(fd, true) was said of them; dup and dupTo give files that stay open; and those of p.more are kept. It returns only if the program can’t run: -2 (ENOENT) or -13 (EACCES) if there is none to run, with nothing done; or, if the program is found but won’t start, minus the errno, with what p asks of the terminal, the group, the files and the directory done, and this program’s signals as they were.

execve(path, args, env) is the kernel’s execve, for a shell, which has looked for the program along its own PATH and set up the child already: the program at path is run with args and with env, NAME=value, for its whole environment. Nothing is searched for, and every fd and signal stays as it is, but that a handled signal does what it does at first: an ignored one stays ignored, as trap '' HUP wants of the command it comes before. It returns only if it can’t: minus an errno, with nothing changed.

A shell moves its own files with dup and dupTo, for 2>&1 and exec >log and around a builtin: dupTo(fd, into) makes into the same open file as fd, closing what into was, and dup gives a new fd for it, the lowest free, as a shell saves a file to give it back. dupAbove(fd, 10) gives one at 10 or above, closed on exec, out of the way of the fds a script names (3>log), as a shell keeps its own. fork copies this program, which goes on from there in both: it is 0 in the copy and the copy’s process id in this one, as a shell runs a builtin or a procedure as a stage of a pipe. Only the thread that calls it is copied, so a program with threads mustn’t; and what Out keeps is copied too, to be written twice, so Out.flush comes first. setsid gives the copy a session of its own, with no controlling terminal, as a daemon does so that closing its terminal doesn’t reach it; it is -1 (EPERM) for a program that leads a process group already, which the copy doesn’t. group is the process group this program is in: a shell starting on a terminal waits until it is foregroundOf(0) before it takes it. access says whether this user, by its real ids, may read, write or execute a file, as test -r, -w and -x ask, which Info.mode alone can’t say; an empty how asks only whether it is there. open refuses executing, with -22 (EINVAL). nonblocking opens a file without waiting: a fifo opened to write waits for a reader and a fifo opened to read waits for a writer, but with nonblocking the open returns at once (-6, ENXIO, for a write with no reader), and a read or write that would wait is -11 later, as setBlocking(fd, false) makes it, and blocking(fd) says which: 1 if they wait, 0 if not. A file open, openMode, openRead or create gives is closed in a program exec or execve starts, as pipe’s are, so that a fifo or a log one program holds doesn’t reach every program it runs; keepOnExec(fd, true) keeps one open, and spawn is unchanged, since it passes its fds and more as before. umask sets the bits taken away from the mode of every file this program, and those it starts, make, and says what they were. envAt gives the environment one variable at a time, from 0, for a shell to list it and to pass it on whole with onlyEnv. env gives “” for a variable that is unset and for one set to nothing; findEnv tells them apart, as TZ needs, unset meaning the local time and empty meaning UTC. setEnv refuses a name that is empty or holds an =, and a 0 in either, with -22; as C’s setenv, it isn’t safe while another thread reads the environment, and what env gave for a variable may be gone once it sets that variable again. getMode reads a terminal’s modes, and setMode sets them again once what was written is sent, so that a shell keeps them for each job: a program stopped by Ctrl-Z with its terminal raw gets it back raw, and the shell its own between. cpuTime says how long the processor ran this program, in its own code and in the system for it, or, if children, the programs it started and has waited for, as time and times say. limit gives a limit, limitFiles say, soft and hard, and setLimit sets them, as ulimit does: a program may raise its soft limit up to the hard one, and lower either. uid is the user this program runs as, euid the one whose rights it has, 0 for root, as a prompt shows #; hostName is the machine’s name. processors counts the processors the program may run on, as the system’s affinity mask allows, for a program that makes a thread to each; it is never less than 1.

wait waits for the program pid to change, for any of this program’s if pid is -1, or for any of the group g if pid is -g, as a shell waits for a job’s programs, and says which one, and how: exited, with its exit status; killed, with the number of the signal that ended it; or stopped, by Ctrl-Z or a signal, with the signal’s number. Without block it doesn’t wait, and is 0 and running if no program changed. A program that has nothing to wait for is -10 (ECHILD). waitExit(pid) is wait that blocks until a program ends, and not for one that is stopped, so that a program waiting for its editor isn’t woken by Ctrl-Z. kill sends a program a signal, sigTerm to end it; to a group, if pid is minus its number.

Signals. catch takes the signals sigs away from what they would do, ending the program most of them, and gives an fd that is ready to read when one comes, so that a program waits for signals with ready and readyOf as it waits for keys or a server. caught gives each signal that came, in turn. A later catch adds to the signals caught and gives the same fd. Catching sigKill or sigStop, or the signals Rt reports, SIGSEGV and SIGFPE, is -22 (EINVAL). ignore makes a signal do nothing, as a shell ignores sigTtou so that it can take its terminal back, and ignore(sig, false) gives it back what it does at first. On a signal that catch took, either gives it up: the signal is no longer caught, with its default action or ignored, and catch’s fd gives the signals still caught. A program that spawn starts begins with neither. ignored(sig) says whether a signal does nothing now, because the program ignored it or because the one that started this one left it so, as a program in the background or under nohup finds sigInt and sigHup: it should leave those alone, and handle or catch the rest.

To wait for a child, a signal or a time, whichever is first, catch sigChld with the other signals and wait in ready on catch’s fd: a child that ends makes sigChld ready there, as a signal that came before the wait does, since catch holds it until caught takes it, so none falls between a wait that found nothing and the sleep after it. When the fd is ready, call caught, then wait(pid, false). handle can’t do this: a signal noted just before the call it should break isn’t seen by it.

handle is for a program that must see a signal while it waits in a system call, as a shell waiting for its foreground program, or for a key, sees Ctrl-C: the signal is noted, and the call it comes during, wait, read, ready and the rest, fails with -4 (EINTR) rather than going on; sleep sleeps its time all the same. came(sig) says whether it came since the last time it was asked. Nothing else runs when the signal comes, so the program does what it does after it, in its own time; Out and Files try again after -4. ignore(sig, false) gives the signal back what it does at first, and the signals catch refuses, handle refuses too.

Time. clock is for measuring how long something takes: it never goes back, and says nothing of the date. now is the date and time, which a person or the network may set back. sleep waits ms milliseconds.

Sockets. connect is for talking to a server on the same machine, an X server at /tmp/.X11-unix/X0 say; connectTcp for one across the network, given its address as numbers, "127.0.0.1" or "::1": turning a name into an address is a library’s work over these. connectUdp gives a socket of datagrams, each send one message to that address and each read one message from it, as a program asks a name server. What a socket receives comes by read, what it sends goes by send, and close ends it. send is write for a socket, except when the other end has closed it: write would stop the program with the signal SIGPIPE, where send returns -32 (EPIPE), so that a program learns its server has gone and can end as it wants. listen and listenTcp are the other side: a server’s socket, on path, which must not be there yet, or on port at addr, "0.0.0.0" or "::" for every address the machine has; accept gives each connection that comes, as a socket of its own. A server started on port 0 gets a port the system chooses, which localPort says, as a test does that must not take a port in use. connectTcp waits as long as the system does, minutes for a host that never answers; connectTcpWithin gives up after ms milliseconds, with -110 (ETIMEDOUT).

listenUdp is the server’s side of connectUdp: a socket of datagrams from anyone, as a name server has. receive gives the next datagram, at most LEN(buf) bytes of it, the rest lost, and a Peer that reply sends an answer to.

closeWrite ends this side’s writing to a socket, so that the other end reads an end of input and can still answer on the same socket: a client sends its request, says it is done, and reads the reply. peer says who is at the other end of a connected socket: for a TCP one its address and port; for a Unix one the user and process that made the connection, as the system recorded them, so that a server can check that its client is the same user instead of trusting a directory’s mode. sendNow is send that never waits: where the socket has no room it gives -11 (errAgain), without making reads on it non-blocking too. socketPair makes two connected stream sockets at once, as a listen, connect and accept would, with no name on disk. Each is closed in a program exec starts. accept gives -103 (errConnAborted) for a client that went before it was taken.

Passing files and sharing memory. A program can give another an open file over a Unix socket: sendFds sends s, at least one byte, and with it fds, at most 16, each a file the other program then has open too; receiveFds reads into buf as read does, puts the fds that came with it in fds, as many as there is room for, closing the rest, and says how many bytes and how many fds. Each is closed in a program exec starts. memFile makes a file that lives in memory, of size zeroed bytes, and mapFile maps it, or any file, so that what one program writes there another sees at once: so a program hands an X server or a Wayland compositor its pixels, by sendFds of a memFile both map, rather than by copying them down a socket. mapFile needs a file open to read and write; mapRead maps one that is open only to read, a dictionary that isn’t the user’s to write, for reading only: a write there stops the program. protect changes what may be done with pages mmap gave, from a page boundary: read, write, both, or neither, so that touching them stops the program, as a guard page after a buffer does, or a reserve mapped in full and opened as it fills. It takes the address as the system does, so with a C library it is that library’s whether an address not on a page boundary is -22 (EINVAL) or rounded down.

readyOf waits on several file descriptors at once, as a program does that listens to a server and a terminal both; a descriptor at its end, or failed, counts as ready, since a read of it won’t wait. It looks at the first 64 of fds, and connect and listen take a path of at most 107 bytes, as struct sockaddr_un holds; a longer one is -36 (ENAMETOOLONG). A path that starts with a zero byte is one of Linux’s abstract names (D-Bus’s unix:abstract=), which has no file: the address is as long as the name, with no zero after it.

poll is readyFor without its limits. Each Poll names a descriptor fd and whether to wait to read from it, to write to it, or both; poll waits up to ms milliseconds (as long as it takes if ms < 0), sets every one’s ready, and gives how many are: all of them, in one call, not the first. It takes any number of descriptors (the list the system wants is on the stack for 64 or fewer, and in memory from mmap, given back before it returns, for more; -12 if there is none). A descriptor at its end or failed is ready, as for readyOf; so is one that isn’t open, and a read or a write of it is -9 (EBADF); a negative fd is never ready. A timeout is 0 and a failure minus an errno (-4, if a signal handle took broke in), where readyFor gives -1 for both. readyFor and readyOf are written over it.

A program that both reads from a descriptor and writes much to it, as a terminal writes what is pasted to its program while it reads what the program writes back, must not wait on either: the program may be waiting for its own writes to be read. setBlocking(fd, false) has a read or a write on fd that would wait return -11 (EAGAIN) at once, a write having written what there was room for; readyFor waits, as readyOf does, for something to read on any of reads or for room to write on any of writes. A descriptor in both is given once, when it is ready for either; the 64 it looks at are reads, then writes.

A Buf, a List, a Map and a Vec take their memory from the allocator init gives them. Buf.add, str and spare stop the program, as a failed check does, if the allocator has no room; room asks first. A program reads into a Buf through spare, then adds what it read to len: s := Buf.spare(b, 4096); n := Sys.read(fd, s); if n > 0 then INC(b.len, n); end;. cut takes back what was added, to a length it had: start := b.len; ...; Buf.cut(b, start);; a length past len stops the program, as an index past the end does. A Vec is Buf for any T: one block, which doubles when it is full, so push costs the same on average however long it grows. all gives the elements as a slice, indexed and checked as any is, and v.len is their number; the slice, and what add gives, are good until the array next grows. pop takes the last element off, keeping the memory. push, add and resize stop the program, as Buf.add does, if the allocator has no room; room asks first: import Lines := Vec([]U8);. Fmt’s format takes the next argument at each {}; {{ and }} stand for { and }. A Map hashes and compares its keys with the procedures it is given: import Count := Map([]const U8, INT, Str.hash, Str.eq);.

Str reads and writes UTF-8. encode writes a character, of at most 10FFFFH, in one to four bytes; a number that isn’t one becomes FFFDH, the character that stands for a wrong one. decode reads the first character of s, and gives FFFDH and 1 for a byte that doesn’t start one rightly, and 0 and 0 for an empty s: a continuation, a byte followed by too few continuations, a surrogate, a character beyond 10FFFFH or one spelled in more bytes than it needs. decodeLast reads the last character in the same way, to walk a string backwards. valid says that decode finds no such byte in s, and chars counts the characters, each such byte one. next walks a string a character at a time, as decode reads them: from 0, it gives the character at i and where the one after it starts, and 0 and -1 when i is at the end, or past it:

c, i := Str.next(s, 0);
while i >= 0 do
    ...                               (* c is a character of s *)
    c, i := Str.next(s, i);
end;

A string is bytes, and Str takes no more of Unicode than UTF-8: lower, upper and eqFold change and match ASCII letters alone, the character tests know ASCII alone, and nothing says how wide a character is on a terminal, nor which spellings of a text are the same.

A space, to isSpace, trim, trimLeft, trimRight and field, is a blank, a tab, a line feed, a carriage return, a vertical tab or a form feed. cut gives what comes before the first sep in s, what comes after it, and true; or s, an empty string and false if s has no sep. field passes the spaces at the start of s and gives the bytes up to the next space or the end, and the rest of s from there; two empty strings if s holds only spaces. They take a string apart without memory of their own, each part a slice of s:

line, rest, more := Str.cut(text, "\n");     (* the first line, and the others *)
key, val, ok := Str.cut(line, "=");
w, rest := Str.field(line);                 (* the words of a line *)
while LEN(w) > 0 do
    Out.str(w); Out.ln;
    w, rest := Str.field(rest);
end;

lower and upper write s’s bytes, so they take a variable’s, not a string literal’s (section 5.10). join and replace add to a Buf as Buf.str does; an empty old adds s as it is.

toInt reads a decimal number, with a - or + before it if any, and nothing else. toHex reads hexadecimal digits, capitals or not, and nothing else: no sign, 0x or H. fromInt writes a number as Out.int does, with a - if it is negative, its bytes the first of the 20 it gives. toU64 reads a decimal number as toInt does, but digits only (no sign), up to the largest U64: what Fmt.uint writes.

fromC and toC are the two ends of a call to C. fromC makes a slice of the bytes at a pointer up to its zero byte, without copying them; nil gives "". toC copies s into out, puts a zero after it and gives PTR(out), so a call reads C.realpath(Str.toC(path, room), ...). out holds LEN(s) + 1 bytes at least; a shorter one stops the program, as any slice does.

base64With and unbase64With take the 64 digits as alphabet and say with pad whether = pads a last group: Base64Url is section 5’s, with - and _, and Base64 section 4’s. Without padding a last group has 2 or 3 digits, and a length 1 more than a multiple of 4 is no base64. base64 and unbase64 are Base64 with padding. In detail, base64 writes s as RFC 4648 (section 4) does: the digits A to Z, a to z, 0 to 9, + and /, and = to pad a last group of 1 or 2 bytes to four. unbase64 reads that and nothing else: its length a multiple of 4, = only as the last one or two bytes, and the bits of the digit before the padding that no byte uses all 0, so a byte string has the one spelling base64 gives it. Line breaks, missing padding and the - and _ of base64url are the caller’s to mend first; unbase64 of such a string is false, and what it wrote into out is not to be used. The caller gives the room, as Fmt does: an out shorter than the comment says stops the program, as indexing past a slice does.

le and be read an unsigned number of up to 8 bytes in a fixed order, little-endian or big-endian, whatever the machine’s own, and putLE and putBE write one; more than 8 bytes stops the program. They are how a file format or a network protocol is read and written:

len := U32(Str.le(header[4..8]));
Str.putBE(packet[0..2], U64(port));

Math.toReal reads a real as a constant is written (section 2), with a - or + before it if any, its point and the digits after it, or its exponent, left out if it has none, and e taken as E: 2, -0.5 and 1.5e-3 are reals to it. It gives the F64 nearest the number, and false for anything else, or a number too big for an F64.

Map.next walks a map: from 0, it gives the next entry and the number to pass for the one after it, and -1 when there are no more. A walk sees each entry once if the map doesn’t change during it:

i, k, v := Names.next(names, 0);
while i >= 0 do
    Fmt.print("{} is {}\n", [Fmt.str(k), Fmt.int(v)]);
    i, k, v := Names.next(names, i);
end;

Sort.sort puts s in the order less gives, in place, without memory of its own, in time n log n at most; two elements equal by less may change places. Math’s procedures are as C’s math.h has them, to within the last bit or so; roundEven is IEEE 754’s default rounding, as Pascal’s Round, where round is C’s. Fmt.real(x, places) writes x with places digits after the point, at most 9, rounded to the nearest; from 1E15 on, with an exponent, as 1.50E17; and nan, inf and -inf as themselves. Fmt.short(x, out) writes x into out, from 0, and gives those bytes: the fewest significant digits that Math.toReal reads back as the same F64, and of two such the nearer x: 0.1, not 0.10000000000000001; 42, with no point; 0.0001; and below 1E-4 or from 1E15 on with an exponent, as 1.5E17 or 5E-324. Zero keeps its sign, 0 or -0, and nan and inf are as real writes them. The longest is Fmt.ShortMost bytes, so a call is var d: [Fmt.ShortMost]U8; Fmt.print("{}", [Fmt.str(Fmt.short(x, d))]);, and a width goes with str. The bytes are out’s: a second call with the same out overwrites them. hex writes capitals and lowHex lower case, neither with a 0x. A width between the braces pads an argument to that many bytes: {2} with spaces on the left, {02} with zeros on the left, after a sign ({04} of -7 is -007), {-10} with spaces on the right. A longer argument is written whole. A { followed by anything but } or a width is dropped, as before. Fmt.print("{2}:{02} U+{04}", [Fmt.int(3), Fmt.int(7), Fmt.hex(0E9H)]) writes 3:07 U+00E9. Fmt.into formats into a slice the caller gives, with no memory of its own, for a library that has no heap: it gives the bytes written, and false if the slice was too short and the text is cut there.

Opt reads a command line by the rules of the C library’s getopt, with GNU’s long options, so that a program’s options behave as every other Unix program’s. The program describes itself once, in a table of Rows: its synopsis lines, its subcommands and its options. The help and the messages for mistakes are made from the table, so they can’t drift from it; the program’s test of p.letter is the only other place an option appears. The parser is a record the program owns, and the table a slice it keeps as long as the parser: a literal written in the call to init lives as long as the procedure that makes it, and a constant, const Rows: []Opt.Row = [...], as long as the program.

A row’s scope is "" for the program itself, or a subcommand’s name: "start", or "remote.add" for a subcommand of remote. An option has a letter, a long name, or both. One with a long name only has a key of its own below '!' for a letter, so that the program can tell it from the others. With a value, the name the help and the messages give it, the option takes a value; with "" it is a flag. A value written in brackets, "[when]", may be left out, and is "" then: it is given only in the option’s own word, --color=always or -calways, never as the next, as getopt’s :: has it, and the help shows it as --color[=when].

The rules are getopt’s:

  • Flags may share a dash: -lw is -l -w. A letter’s value is the rest of its word, -bdev, or the whole next word, -b dev, even one that starts with a dash or is empty; in a group, the first letter that takes a value takes the rest, -qn12.
  • A long option is written in full, with its value after a = or in the next word: --bar=dev, --bar dev. An abbreviation is unknown, not guessed, so that adding an option never breaks a script. A value given to a flag, --follow=x, is a mistake.
  • -- ends the options, and isn’t an operand; - alone is one. The options end at the first operand, so in keep start site python -m http.server the -m is python’s.
  • In a scope with no option whose letter is a digit, a word of - and a digit, such as -33.87, is an operand, and so ends the options. A scope that gives a digit a letter, as head -5 has, reads it as an option.
  • Each scope has its own options. An option given twice is read twice.

number reads the value as Str.toInt does. operand reads what options are left first, and the program doesn’t see them. So does at, which says where the operands are: the arguments from operand’s next on are Files.arg(i) for i from at(p) to ARGC() - 1, so that an interpreter hands a script its arguments as they are:

script, ok := Opt.operand(p);       (* tery file arg ... *)
first := Opt.at(p);                 (* file's own arguments, from here on *)

-h or --help among a scope’s options prints its help on standard output and ends the program with status 0. init and scope answer it, looking through the scope’s options before next gives one, so that the program has done nothing yet: keep -v -h -x prints the help, and the program never sees -v, nor the mistake. The help is the scope’s synopsis lines, a blank line, and its subcommands, its options and the help itself, each with its line of help:

usage: keep start [-b label] name command [argument ...]

  -b, --bar label   show the job in the bar as label
  -h, --help        print this and exit

A scope with several synopsis lines has the others indented under the first; one with none, usage: and its words, as usage: keep start. A scope may give -h to an option of its own, as grep’s “no file names”; help there is --help alone, and its row in the help has no letter.

A mistake on the command line is a sentence on standard error, the program’s name first, then the scope’s synopsis lines, as the help begins, and status 2:

keep: unknown option -x
usage: keep start [-b label] name command [argument ...]

The sentences are unknown option -x (or --name, up to its =), -b needs a label, --follow takes no value and --wait wants a number from 1 to 600, not '0'; for a number with no top, given the largest I64 for hi, --jobs wants a number from 1 up, not '0'. refuse refuses a value the program reads itself, as number refuses one, naming the option as the user wrote it, -b or --bar: Opt.refuse(p, "a label with no spaces") writes keep: -b wants a label with no spaces, not 'a b', and the synopsis lines. p.spelt is that spelling, for the program’s own sentences. fail writes the program’s own mistakes the same way, but alone, so that the sentence can say where the help is: keep: no command; see keep -h. misuse writes one with the scope’s synopsis lines after it, for a mistake in the operands: Opt.misuse(p, "no tests named").

A mistake in the table is the program’s, not its user’s. init checks the table before it reads a word, and ends the program with status 1: keep: option table, row 3: the option is in the scope already. The others are an option with neither a letter nor a long name, a long name with = in it, a letter -, a value with one bracket but not the other, and --help in the table, since it is Opt’s.

Width says how many columns of a terminal text takes, for a program with a screen that wraps its lines and cuts them at the window’s edge.

module Width;
proc width*(c: I32): INT;      (* the columns the character c takes: 0, 1 or 2 *)
proc columns*(s: []const U8): INT;   (* the columns the UTF-8 text s takes *)

A combining mark, a format character, a control and Hangul’s medial and final jamo take 0 columns; an ideograph, a kana, most emoji and the rest that Unicode calls East Asian Wide or Fullwidth take 2; every other character takes 1, the ambiguous ones among them, as most terminals draw them. These are the C library’s wcwidth’s answers, but for a control, which is -1 there. Width knows characters, not clusters: an emoji joined to another by a zero width joiner, or a flag, counts as its parts. Its tables, about 4 KB, come from Unicode’s data, made again by tools/Widths.raz for a new version of Unicode; a program that imports Width and calls neither procedure carries none of them.

Rand, Check and Prop are for testing a program, and are standard library, not core: a target may leave them out. raztest(1) builds and runs the tests that use them.

Rand is a seeded generator of numbers, splitmix64: one U64 of state. The same seed gives the same numbers on every machine, so a run can be replayed. It is not for secrets.

module Rand;
type Rand* = record ... end;
proc init*(var r: Rand; seed: U64);     (* starts r at seed; any seed, 0 too *)
proc next*(var r: Rand): U64;           (* the next number, all 64 bits of it *)
proc below*(var r: Rand; n: U64): U64;  (* 0 to n - 1, each as likely as another; n = 0 stops the program *)
proc range*(var r: Rand; lo, hi: I64): I64;   (* lo to hi, both included; lo must not exceed hi *)
proc seed*(): U64;                      (* a fresh seed from the kernel, to print and give back to init *)
module Dice;
import Rand, Check;

(* Five rolls of a die from seed, as the digits of a number. *)
proc rolls(seed: U64): INT;
var r: Rand.Rand; i, v: INT;
begin
    Rand.init(r, seed);
    for i := 1 to 5 do v := v * 10 + INT(Rand.range(r, 1, 6)); end;
    return v;
end;

proc main*;
begin
    Check.int("the same seed, the same rolls", rolls(7), rolls(7));
    Check.ok(rolls(7) >= 11111, "every die shows 1 or more");
    Check.ok(rolls(7) <= 66666, "every die shows 6 or less");
end;

end Dice.

Check says what a test expects. A check that fails writes FAIL and its words on standard error, with what it got and what it wanted where they differ; the program goes on. At its end, if any check failed, it says how many and exits with status 1, and a run with none failed says nothing and keeps its own status. No call is needed at the end: the first check asks Rt.atExit to make it. A program that stops after a check failed, by Rt.stop or a failed check of the language, ends with status 1 too. mute is for Prop, which searches with the checks silenced.

module Check;
proc ok*(cond: BOOL; what: []const U8);                 (* fails, saying what, when cond is false *)
proc str*(what, got, want: []const U8);                 (* fails when got is not want; shows both, escaped, and the byte where they differ *)
proc int*(what: []const U8; got, want: I64);            (* fails when got is not want; shows both *)
proc mute*(on: BOOL);                             (* while on, checks say nothing and are not counted *)
proc mutedFailures*(): INT;                       (* how many failed since mute was turned on *)
module Digits;
import Check;

(* How many decimal digits n, not negative, takes. *)
proc count(n: INT): INT;
var d: INT;
begin
    d := 1;
    while n >= 10 do n := n div 10; INC(d); end;
    return d;
end;

proc main*;
begin
    Check.int("0 is one digit", count(0), 1);
    Check.int("9 is one digit", count(9), 1);
    Check.int("10 is two digits", count(10), 2);
    Check.ok(count(1000000) = 7, "a million is seven digits");
end;

end Digits.

Prop tests a property: a procedure that draws values and checks them with Check. A case is the bytes the property drew, and Source gives them as a number, a choice, a flag or a string of bytes; fewer and smaller bytes give simpler values. When a case fails, Prop shrinks it by changing its bytes and running the property again, so no type needs a shrinker of its own, and it saves the case. A property that draws only bytes is a fuzzer.

module Prop;
type Source* = record ... end;
type Property* = proc(var s: Source);              (* draws from s, checks with Check *)
proc bits*(var s: Source): U64;                    (* 64 bits, from 8 bytes, the first the highest *)
proc int*(var s: Source; lo, hi: I64): I64;        (* lo to hi, both included; zeros give lo *)
proc pick*(var s: Source; n: INT): INT;            (* 0 to n - 1; n at least 1 *)
proc bool*(var s: Source): BOOL;
proc bytes*(var s: Source; max: INT; var b: Buf.Buf);   (* b, emptied, then given at most max bytes *)
proc check*(name: []const U8; p: Property);              (* runs p on the saved cases, then on fresh ones *)

check runs p on each case saved in the directory $PROP_DIR/name (test/seeds/name if PROP_DIR is unset), then on $PROP_CASES fresh cases (100 if unset), from the seed $PROP_SEED or a new one, or for as many seconds as $PROP_TIME says, if it is set. Each is a whole number. A property that holds says nothing and writes no file. The first case that fails is shrunk and saved in a file named by its hash; standard error says the seed and the file; the shrunk case runs once more with Check heard, and the program ends with status 1. A saved case is run first the next time, so a failure stays found until it is mended; keep the directory with the tests. A case that stops the program, by Rt.stop, a failed check of the language or a signal, can’t be shrunk; it is saved as it was, when the program ends. raztest --seed and --fuzz set PROP_SEED and PROP_TIME.

module Reverse;
import Prop, Check, Buf, Heap;

var
    b, was: Buf.Buf;    (* the bytes drawn, and a copy of them *)

(* Turns s round, in place. *)
proc reverse(s: []U8);
var i: INT; c: U8;
begin
    for i := 0 to LEN(s) div 2 - 1 do
        c := s[i]; s[i] := s[LEN(s) - 1 - i]; s[LEN(s) - 1 - i] := c;
    end;
end;

(* Reversing any string twice gives it back. *)
proc twice(var s: Prop.Source);
begin
    Prop.bytes(s, 64, b);
    Buf.reset(was);
    Buf.str(was, Buf.bytes(b));
    reverse(Buf.bytes(b));
    reverse(Buf.bytes(b));
    Check.str("reversed twice", Buf.bytes(b), Buf.bytes(was));
end;

proc main*;
begin
    Buf.init(b, Heap.heap);
    Buf.init(was, Heap.heap);
    Prop.check("reverse", twice);
end;

end Reverse.

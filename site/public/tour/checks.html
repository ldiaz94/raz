When it goes wrong

Fail.raz
module Fail;
import Out;

proc show(a: []INT; i: INT);
begin
    Out.int(a[i]);
    Out.ln;
end;

proc main*;
var a: [3]INT; i: INT;
begin
    for i := 0 to 3 do
        show(a, i);
    end;
end;

end Fail.
0
0
0
Fail.raz:6:15: index 3 is out of range for a length of 3
  in Fail.show at Fail.raz:6:15: i = 3
  in Fail.main at Fail.raz:14:9: i = 3

Every index and slice is checked. A failed check says where it failed and with what values, then the calls under way with their variables, and ends the program with status 2. The three 0s are what it printed before the fourth pass went one past the end.

Reading the message

The first line is the place of the offending expression: file, line and column, then what failed and the numbers involved. Each in line after it is a call still under way, innermost first, with the basic-typed variables it held. That is usually enough to see the bug without a debugger.

Other failures

The same shape of message tells of a nil pointer, a division by zero, a bad slice and a stack overflow. Each of them stops the program with status 2, and never runs on with a wrong value.

Nilp.raz
module Nilp;
import Out;
import SYSTEM;

type Node = record val: INT; next: ^Node; end;

proc last(n: ^Node): INT;
begin
    while n^.next # nil do n := n^.next; end;
    return n^.val;
end;

proc main*;
var a, b: Node;
begin
    a.val := 1; b.val := 2;
    a.next := SYSTEM.ADR(b);
    Out.int(last(SYSTEM.ADR(a))); Out.ln;
    Out.int(last(nil)); Out.ln;
end;

end Nilp.
2
Nilp.raz:9:11: stopped by a nil pointer
  in Nilp.last at Nilp.raz:9:11: n = nil
  in Nilp.main at Nilp.raz:19:5
Zero.raz
module Zero;
import Out;

proc ratio(a, b: INT): INT;
begin
    return a div b;
end;

proc main*;
var n: INT;
begin
    Out.int(ratio(10, 3)); Out.ln;
    Out.int(ratio(10, n)); Out.ln;       (* n is zero: every variable starts at zero *)
end;

end Zero.
3
Zero.raz:13:5: stopped by a division fault
  in Zero.main at Zero.raz:13:5: n = 0
Slicing.raz
module Slicing;
import Out;

proc main*;
var a: [5]INT; s: []INT; hi: INT;
begin
    hi := 7;
    s := a[2..5];
    Out.int(LEN(s)); Out.ln;
    s := a[2..hi];                       (* past the end *)
    Out.int(LEN(s)); Out.ln;
end;

end Slicing.
3
Slicing.raz:10:12: slice 2..7 is out of range for a length of 5
  in Slicing.main at Slicing.raz:10:12: hi = 7

In every case the output before the failure was written first. Out's buffer is flushed by the failure, so what the program printed is never lost to the crash.

A constant can fail at compile time

A division by a zero constant, or a constant index out of range, is not a run-time failure at all; the compiler says it at the line, so you never ship it.

Early.raz
module Early;
import Out;

proc main*;
var a: [3]INT;
begin
    a[3] := 1;
    Out.int(10 div 0); Out.ln;
end;

end Early.
$ raz Early.raz
Early.raz:7:7: error: index 3 is out of range for a length of 3
    7 |     a[3] := 1;
      |       ^
Early.raz:8:13: error: division by zero
    8 |     Out.int(10 div 0); Out.ln;
      |             ^^^^^^^^
raz: 2 errors

Looking at where you are

Rt.trace prints the calls under way, as a failure does, whenever you ask. It writes to standard error and the program goes on. It is the cheapest debugging tool there is.

Where.raz
module Where;
import Rt;

proc inner(depth: INT);
begin
    if depth = 0 then Rt.trace; return; end;
    inner(depth - 1);
end;

proc main*;
begin
    inner(2);
end;

end Where.
  in Where.inner at Where.raz:6:23: depth = 0
  in Where.inner at Where.raz:7:5: depth = 1
  and 1 more the same
  in Where.main at Where.raz:12:5

Leaving the checks out

A module that is sure of its indexes may say check off; after its imports and links, for speed. The module's own indexing and slicing is then unchecked, so an index out of range reads or writes whatever it reaches. Every other check stays (nil and division), and callers of the module keep theirs. Use it for a measured inner loop, never as a first step.

For gdb and the profiler

The program carries names and line numbers, so gdb can break at Fail.raz:6 and show raz source. RAZ_PROFILE=1 in the environment makes a program sample itself every millisecond and say at the end where its time went, by procedure and by line.

Save a program under its module’s name and run it with raz run Name.raz.
